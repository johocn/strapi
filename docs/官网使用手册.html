第一章系统总览

1.1 GEO 体系定位与核心逻辑

传统 SEO 解决的是"搜索引擎能不能找到你"的问题，GEO（Generative Engine Optimization）解决的是"AI 模型能不能正确理解你、引用你、推荐你"的问题。当用户向 ChatGPT、Perplexity、文心一言提问"XX 行业哪家公司靠谱"时，AI 的回答来自它训练和检索时抓取的网页内容。如果你的官网内容结构混乱、信息矛盾、缺乏机器可读的结构化数据，AI 就会跳过你或引用竞争对手。

zhao-website 插件的 GEO 体系围绕三个核心能力构建：

核心能力技术实现解决的问题
第一真值first-truth-policy 内容类型 + llms.txt 输出确保 AI 抓取到的是企业唯一权威信息，而非过时或矛盾版本
结构化数据schema-builder 服务生成 JSON-LD让搜索引擎和 AI 以标准格式理解页面内容类型（Article/Product/FAQ 等）
内容可达性sitemap.xml + robots.txt + RSS/Atom feed确保所有发布内容能被搜索引擎和 AI 爬虫发现和抓取

不做这套体系的直接后果：官网有内容但 AI 不知道你存在，搜索结果里出现的信息可能是第三方平台的二手描述而非你的原文，用户在 AI 对话中问起你的产品时得到的是模糊甚至错误的答案。

1.3 发布闭环机制

每一条内容从创建到产生流量效果，经过以下闭环链路：

内容创建 → 填写 SEO/GEO 字段 → 发布 (status=published)
↓
Lifecycle 触发 → 标签索引同步 → 知识图谱同步 → 搜索引擎推送
↓
Sitemap 更新 → llms.txt 更新 → RSS Feed 更新 → 缓存失效
↓
搜索引擎收录 → AI 模型抓取 → 用户搜索/提问触达 → 流量回流官网

Lifecycle 钩子在内容发布（afterCreate / afterUpdate）时自动触发四个动作：标签索引同步（将文章标签写入全局标签索引，供标签页聚合展示）、知识图谱同步（将内容关联的实体写入知识图谱，构建实体关系网络）、搜索引擎推送（向百度/Google 主动推送 URL，加速收录）、缓存失效（清空 SEO 输出缓存，确保下次请求拿到最新内容）。删除时触发标签索引移除和缓存失效。

1.4 与官网、媒体中心、课程中心的联动逻辑

内容发布后会在多个子系统产生联动效果：

联动系统联动机制数据流向
官网前端内容通过 /api/v1/articles/:slug 等公开 API 暴露，前端 SSR 渲染时注入 SEO meta 和结构化数据zhao-website → 公开 API → Nuxt3 前端
媒体中心文章可关联 sourceArticleDraft（来自 zhao-studio 内容工作室），实现草稿到发布的跨系统流转zhao-studio 草稿 → zhao-website 文章

知识图谱所有内容类型通过 mainEntity 和 mentionedEntities 关联知识实体，构建跨内容类型的实体关系网各内容类型 → knowledge-entity → 知识图谱 API

这套联动逻辑的核心价值在于：一次发布，多端触达。你在官网发布一篇产品文章，搜索引擎通过 sitemap 发现它，AI 模型通过 llms.txt 抓取它，媒体中心可以引用它，课程中心可以关联它，知识图谱会更新实体关系——所有这些不需要手动操作，由 Lifecycle 钩子自动完成。

关键理解

每一个字段都有它在 GEO 链路中的位置。标题写得好不好，直接决定 AI 是否引用你；结构化数据填不填，决定搜索引擎是否展示富媒体结果；allowIndex 开关决定了这条内容是否进入 sitemap 和 llms.txt——这些不是可选项，而是决定流量效果的必填项。

第二章资讯文章

2.1 设计目的与 GEO 角色

资讯文章是官网内容产出的主力载体。它的设计目的是建立企业在特定领域的知识权威性——当用户或 AI 搜索"XX 行业怎么做"时，你的文章是那个被引用的答案来源。

在 GEO 体系中，文章承担三个角色：知识播种（为 AI 模型提供可学习的行业知识语料）、长尾流量入口（通过覆盖行业长尾关键词获取搜索流量）、实体权重积累（每篇文章关联的知识实体在知识图谱中的置信度随引用次数增长）。

不做文章发布的后果：AI 模型在回答行业问题时不会提到你的企业，搜索长尾词时流量全部流向竞争对手的内容平台，你的产品页面缺乏内链支撑导致权重低迷。正确使用的效果：一篇高质量行业文章可以在发布后 2-4 周内被搜索引擎收录，3-6 个月内开始稳定获取长尾搜索流量，同时被 AI 模型纳入回答引用来源。

2.2 页面运作原理

数据上下游流转

环节数据流向触发机制
上游输入zhao-studio 草稿 → sourceArticleDraft 关联 → 文章创建工作室发布草稿时可选推送到官网
创建/更新填写字段 → 保存 → afterCreate/afterUpdate LifecycleStrapi 内容管理器保存操作
Lifecycle 触发标签索引同步 → 知识图谱同步 → 搜索引擎推送 → 缓存失效自动，无需手动干预
下游输出公开 API /api/v1/articles/:slug → 前端 SSR → sitemap → llms.txt → RSS feed前端请求 / 爬虫抓取
流量回流搜索引擎结果 → 用户点击 → 官网文章页 → 内链引导至产品页用户搜索行为

发布触发的机制链

当文章 status 从 draft 变为 published 时，系统按顺序执行：

  1. syncTagIndex — 将文章关联的标签写入 zhao_tag_indices 表，标签聚合页可以展示这篇文章
  2. knowledgeGraphSync — 将文章的 mainEntity 和 mentionedEntities 同步到知识图谱，更新实体关系和置信度
  3. triggerSyncEvent — 发布同步事件，通知其他子系统（如媒体中心）内容已更新
  4. pushToSearchEngines — 向百度站长平台和 Google Search Console 主动推送文章 URL，加速收录
  5. cache.invalidate — 清空 SEO 输出缓存，确保 sitemap、llms.txt、RSS feed 下次生成时包含最新内容

与各系统的联动

文章发布后，官网前端通过 API 获取文章内容并渲染，同时注入 seoTitle、seoDescription、ogImage 等 meta 标签和 schemaJson 结构化数据。媒体中心通过 sourceArticleDraft 关联回溯草稿来源。课程中心通过共享的 knowledge-entity 实现教程与文章的知识互联。AI 抓取通过 llms.txt 的 Pages 清单发现文章 URL，抓取后纳入模型训练/检索语料。

字段四件套详解

title string / maxLength:200 必填 SEO GEO
设计初衷
文章的展示标题，同时作为 <title> 和 <h1> 的默认值。当未设置 seoTitle 时，搜索引擎和 AI 使用此字段。
作用原理
写入数据库后，公开 API 返回此字段；前端 SSR 渲染为 <h1>；seo-meta 服务在未配置 seoTitle 时回退使用此值生成 <title> 标签。
标准填写规范
15-35 个中文字符。格式建议：[核心关键词] + [修饰词] + [价值点]。例如"2026 年企业数字化转型指南：从战略到落地的完整路径"。标题中应包含目标搜索关键词，避免纯品牌词或纯情感表达。
错误后果
标题超过 60 字符时搜索引擎会截断显示；不含关键词的标题无法匹配搜索查询；与 seoTitle 同时设置但内容差异过大时，AI 抓取可能产生语义混淆；标题重复（多篇相同标题）会被搜索引擎判定为重复内容。
slug uid / targetField:title 必填 SEO
设计初衷
生成文章的 URL 路径标识，决定 /articles/:slug 的最终地址。URL 是搜索引擎和 AI 抓取的第一个信号。
作用原理
系统根据 title 自动生成拼音/英文 slug，也可手动修改。写入后不可随意变更——变更会导致旧 URL 失效，需配合 redirect-rule 做 301 跳转。
标准填写规范
全小写英文，单词用连字符分隔，长度 10-60 字符。例如 enterprise-digital-transformation-guide-2026。包含核心关键词的英文翻译。禁止使用中文、特殊符号、下划线。
错误后果
使用中文 slug 会导致 URL 编码后过长且不可读；随意修改已发布文章的 slug 会导致 404 错误和搜索引擎收录丢失；slug 中堆砌关键词（如 best-cheap-fast-service）会被搜索引擎判定为垃圾链接。
excerpt text 选填 SEO GEO
设计初衷
文章摘要，用于列表页展示、搜索结果描述回退、llms.txt 中的页面简介。当未设置 seoDescription 时，搜索引擎使用此字段作为描述。
作用原理
在文章列表 API 中返回；llms-txt 服务将其作为页面描述输出到 llms.txt 文件中；seo-meta 服务在未配置 seoDescription 时回退使用此值。
标准填写规范
80-160 个中文字符。用 1-2 句话概括文章核心观点和价值。包含主要关键词。避免直接复制正文第一段——摘要应独立概括全文。
错误后果
留空时搜索引擎自动从正文提取，可能选取不相关段落；过长会被截断影响搜索结果展示效果；与正文内容不符会降低点击率。
content text 必填
设计初衷
文章正文内容，支持富文本/Markdown 格式。这是 AI 模型抓取的核心语料来源。
作用原理
通过 API 返回给前端渲染；AI 爬虫抓取页面 HTML 后提取正文内容用于训练和检索；wordCount 和 readingTime 基于此字段计算。
标准填写规范
正文 800-3000 字为宜。结构清晰：开头点明主题（100 字内），中间分段论述（每段 200-400 字），结尾总结。使用 H2/H3 分段。包含数据、案例、操作步骤等具体信息。避免空洞的修饰性语句。
错误后果
正文过短（<300 字）会被搜索引擎判定为薄内容；纯图片无文字会导致 AI 无法抓取；内容与标题不符会增加跳出率，降低页面权重。
coverImage media 选填 SEO
设计初衷
文章封面图，用于列表页缩略图、文章页顶部展示、社交分享卡片。同时作为 sitemap 图片条目输出。
作用原理
图片 URL 写入 sitemap 的 <image:image> 标签；未设置 ogImage 时作为社交分享图片；前端列表页渲染为缩略图。
标准填写规范
尺寸 1200x630px 或同比例，格式 JPG/WebP，大小不超过 300KB。图片内容应与文章主题相关。禁止使用纯文字图、纯色背景或与内容无关的装饰图。
错误后果
图片过大导致页面加载缓慢，影响 Core Web Vitals 评分；无封面图的文章在列表页展示效果差，点击率降低 30-50%。
category relation → article-category 选填
设计初衷
文章分类，用于官网导航结构和内容聚合。分类页本身也是 SEO 着陆页。
作用原理
关联到 article-category 内容类型；分类页通过 API 聚合该分类下所有文章；面包屑导航基于分类生成结构化数据。
标准填写规范
每篇文章选择一个最相关的分类。分类应在创建文章前规划好，避免频繁新增分类导致结构混乱。
错误后果
不设分类的文章不会出现在分类聚合页，减少内链入口；选错分类导致用户导航体验差和跳出率升高。
tags relation → tag (manyToMany) 选填 GEO
设计初衷
文章标签，用于跨内容类型的主题关联。标签页是长尾关键词着陆页。
作用原理
Lifecycle 的 syncTagIndex 将标签写入全局索引；标签聚合页展示相关文章、产品、案例；知识图谱通过标签建立实体关联。
标准填写规范
每篇文章选择 3-7 个标签。标签应为具体的关键词而非宽泛的分类名。例如使用"数字化转型""CRM 系统"而非"技术""管理"。
错误后果
标签过多（>10 个）会分散主题焦点；标签过宽泛失去长尾匹配价值；不设标签的文章缺少跨内容关联入口。
seoTitle string / maxLength:60 选填 SEO
设计初衷
独立设置搜索引擎结果页显示的标题，允许与页面 <h1> 标题不同。用于在搜索结果中优化点击率。
作用原理
写入 <title> 标签和 og:title。未设置时回退到 title 字段。搜索引擎在结果页展示此值（可能根据查询动态截断）。
标准填写规范
25-35 个中文字符（搜索引擎通常展示 30-40 字符）。格式：[核心关键词] - [品牌名] 或 [吸引力描述] | [品牌名]。前置关键词，后置品牌。
错误后果
超过 60 字符会被截断；关键词堆砌会被搜索引擎降权；与页面内容不符会导致高跳出率，长期降低排名。
seoDescription string / maxLength:160 选填 SEO
设计初衷
搜索引擎结果页的描述文本，直接影响点击率。同时作为 AI 抓取时的页面摘要。
作用原理
写入 <meta name="description"> 和 og:description。搜索引擎不一定采用此值（可能自行提取正文），但正确设置时采纳率约 70%。
标准填写规范
70-155 个中文字符。包含核心关键词。以行动号召或价值主张结尾。例如"了解 2026 年企业数字化转型的 5 个关键步骤，附实施时间表和成本评估方法。"
错误后果
留空时搜索引擎从正文提取，可能选取不理想段落；超过 160 字符被截断；纯关键词罗列（无完整句子）会被搜索引擎忽略。
seoKeywords string / maxLength:200 选填
设计初衷
页面关键词声明。虽然主流搜索引擎已不再以此作为排名因素，但部分中文搜索引擎仍参考此字段。
作用原理
写入 <meta name="keywords"> 标签。部分中文搜索引擎（搜狗、360）仍将其作为辅助参考。
标准填写规范
3-5 个关键词，逗号分隔。选择页面实际涉及的具体词汇，不要堆砌不相关热词。
错误后果
堆砌大量无关关键词可能被搜索引擎判定为作弊；留空无实质影响。
canonicalUrl string / maxLength:500 选填 SEO
设计初衷
规范 URL 声明，解决重复内容问题。当文章在多个平台发布时，告知搜索引擎哪个是原始版本。
作用原理
写入 <link rel="canonical"> 标签。搜索引擎将权重集中到规范 URL 上，避免重复内容惩罚。
标准填写规范
原创文章留空（系统自动生成规范 URL）。转载或同步发布到其他平台的文章，填写官网原始 URL。格式：https://example.com/articles/slug。
错误后果
填错 URL 会导致权重转移到错误页面；将原创文章的 canonical 指向其他平台会导致自己官网失去收录。
ogImage media 选填
设计初衷
社交分享时显示的图片，独立于封面图。允许为不同平台定制分享图片。
作用原理
写入 og:image 标签。微信、微博、LinkedIn 等平台抓取此 URL 生成分享卡片。
标准填写规范
尺寸 1200x630px，JPG/WebP 格式，小于 300KB。图片上可叠加标题文字和品牌 logo。留空时回退到 coverImage。
错误后果
图片过小（<200px）在社交平台显示模糊；图片过大导致分享加载缓慢；无图片的文章分享时显示空白卡片，点击率降低 60% 以上。
allowIndex boolean / default:true 选填 SEO GEO
设计初衷
控制此文章是否允许被搜索引擎和 AI 抓取。这是内容进入 GEO 体系的总开关。
作用原理
设为 false 时：文章不进入 sitemap、不进入 llms.txt、页面头部输出 <meta name="robots" content="noindex">。设为 true 时：正常进入所有 SEO/GEO 输出通道。
标准填写规范
正式发布的文章设为 true。内部测试文章、过期活动公告、仅面向登录用户的内容设为 false。
错误后果
误将重要文章设为 false 会导致内容完全无法被搜索引擎和 AI 发现；将应保密的内容设为 true 会导致信息泄露。
sitemapPriority / sitemapFrequency decimal / enumeration 选填 SEO
设计初衷
在 sitemap.xml 中声明此页面的优先级和更新频率，引导搜索引擎爬虫分配抓取资源。
作用原理
sitemapPriority 写入 <priority> 标签（0.0-1.0）；sitemapFrequency 写入 <changefreq> 标签。搜索引擎将其作为爬虫调度参考（非强制）。
标准填写规范
文章默认 priority=0.7, frequency=weekly。重磅文章可调至 0.8/daily；低价值内容降至 0.5/monthly。
错误后果
所有文章都设为 1.0/always 会使优先级信号失效（搜索引擎忽略全高优先级的 sitemap）；设置与实际更新频率不符会影响爬虫信任度。
mainEntity / mentionedEntities relation → knowledge-entity 选填 GEO
设计初衷
将文章与知识图谱中的实体关联。mainEntity 是文章的核心主题实体，mentionedEntities 是文章中提及的其他实体。
作用原理
Lifecycle 的 knowledgeGraphSync 将关联写入知识图谱；结构化数据中的 about 和 mentions 字段基于此生成；AI 抓取时通过实体关联理解内容的主题归属。
标准填写规范
每篇文章设置 1 个 mainEntity（文章核心讨论的产品/概念/人物）。提及 2-5 个 mentionedEntities。实体需先在知识图谱中创建。
错误后果
不设实体的文章在知识图谱中孤立，无法被实体查询触达；关联错误实体会导致 AI 对企业业务范围产生误解。
brandVoiceRef relation → brand-voice 选填 GEO
设计初衷
关联品牌话术库，确保文章用词与企业标准话术一致。AI 抓取时获得统一的品牌表述。
作用原理
关联到 brand-voice 内容类型；llms.txt 的 Brand Voice 部分会输出关联的话术内容；编辑时可在侧边栏参考标准话术。
标准填写规范
选择与文章主题最相关的品牌话术条目。例如产品评测文章关联产品定位话术，行业分析文章关联行业观点话术。
错误后果
不关联话术的文章可能使用了非标准表述，导致 AI 对品牌认知不一致；关联错误话术会误导内容方向。
sourceType / sourceUrl enumeration / string 选填
设计初衷
声明内容来源类型（原创/工作室/外部）和原始来源 URL，用于原创性追溯和版权管理。
作用原理
sourceType 枚举值：original（原创）、studio（内容工作室产出）、external（外部来源）。sourceUrl 记录原始来源链接。
标准填写规范
原创文章选 original；从 zhao-studio 工作室发布的选 studio 并关联 sourceArticleDraft；转载内容选 external 并填写原始 URL。
错误后果
转载内容未标记来源可能引发版权纠纷；原创内容误标为外部来源会失去原创权重优势。
status enumeration / default:draft 必填
设计初衷
控制文章的生命周期状态。只有 published 状态的文章才会进入公开 API、sitemap 和 llms.txt。
作用原理
枚举值：draft（草稿，仅管理后台可见）、published（已发布，公开可见）、archived（已归档，从公开输出中移除但保留数据）。状态变更触发 Lifecycle。
标准填写规范
创建时默认 draft，完成所有字段填写和自检后改为 published。过期内容改为 archived 而非删除。
错误后果
未发布的文章无法被搜索引擎和 AI 发现；误将草稿发布会导致未完善内容被收录，影响站点质量评分。

禁止发布的内容类型

4. 过时未更新内容 — 发布后长期不更新，数据/结论已过时。后果：用户跳出率高，AI 引用过时信息损害品牌。

5. 与品牌定位不符内容 — 为追热点发布与企业业务无关的内容。后果：稀释主题相关性，AI 对企业业务范围产生混淆。

第三章产品/方案

3.1 设计目的与 GEO 角色

产品/方案页面是官网的转化核心。它的设计目的是向搜索引擎和 AI 模型提供结构化的产品事实声明——产品名称、价格、可用性、规格参数，这些信息以 Product + Offer 结构化数据格式输出，让 AI 在用户询问"XX 产品多少钱""XX 类产品推荐"时直接引用你的产品信息。

在 GEO 体系中，产品页承担三个角色：事实锚点（通过结构化数据向 AI 声明产品的核心属性，防止第三方平台提供错误信息）、转化着陆页（承接文章和案例的内链流量，引导用户咨询/试用）、价格信号源（价格和可用性数据通过 sitemap 和结构化数据输出，影响购物搜索和 AI 推荐结果）。

不做产品页的后果：AI 模型在回答产品相关问题时使用第三方平台（如电商、评测网站）的数据，可能包含过时价格或错误规格；购物搜索结果中不出现你的产品；内链流量没有转化着陆点。正确使用的效果：产品结构化数据被 Google 收录后可在搜索结果中展示价格和库存状态，AI 模型在推荐产品时引用你的官方参数。

3.2 页面运作原理

数据上下游流转

环节数据流向触发机制
上游输入产品规划文档 → 手动创建产品记录内容运营在管理后台创建
创建/更新填写字段 → 保存 → Lifecycle 触发Strapi 内容管理器保存
Lifecycle 触发标签索引 → 知识图谱 → 搜索引擎推送 → 缓存失效自动执行
结构化数据生成schema-builder 生成 Product schema（含 offers）→ 注入页面前端请求时动态生成
下游输出公开 API → 前端产品页 → sitemap（priority 0.8）→ llms.txt Pages + Facts爬虫抓取 / 前端请求
案例联动产品 ↔ cases 关联 → 产品页展示相关案例双向关联

结构化数据输出

产品页生成的 JSON-LD 结构化数据包含 Product 类型，嵌套 Offer 对象（含 price、priceCurrency、availability）。这些数据让搜索引擎在购物搜索中展示价格和库存信息，让 AI 模型在推荐产品时引用准确的产品参数。同时，产品的 features 和 specifications 通过 llms.txt 的 Pages 部分输出，成为 AI 可读的产品事实。

类别角色说明

产品运营负责产品页面维护和 SEO 优化
市场负责人审核产品定位和价格信息的对外一致性
禁止操作人群销售人员可能将谈判价格填入公开价格字段

发布内容最终用途：产品页面同时服务于搜索引擎购物搜索（通过 Product schema 展示价格和库存）、AI 产品推荐（通过 llms.txt 提供产品事实）、官网转化（用户了解产品后发起咨询/试用）、案例关联展示（产品页展示相关落地案例增强说服力）。价格和规格数据的准确性直接影响 AI 是否信任你的产品信息。

3.4 字段四件套详解

name string / maxLength:200 必填 SEO GEO
设计初衷
产品/方案的正式名称，作为结构化数据 Product.name 输出。AI 模型在推荐产品时使用此名称。
作用原理
写入 <h1> 和 Product schema 的 name 字段；llms.txt Pages 部分使用此名称作为链接文本；未设置 seoTitle 时作为 <title> 回退值。
标准填写规范
使用产品的官方正式名称，包含品牌名和产品线名。例如"智造云 MES 系统"而非"MES"。长度 4-30 字。避免使用内部代号或英文缩写（除非是公认的行业标准缩写）。
错误后果
使用内部代号导致 AI 和用户无法识别产品；名称频繁变更会导致知识图谱实体断裂；名称与第一真值中的声明不一致会降低 AI 信任度。
tagline string / maxLength:200 选填 GEO
设计初衷
产品一句话定位描述，用于列表页展示和 llms.txt 中的产品简介。AI 抓取时这是理解产品定位的第一信号。
作用原理
在产品列表 API 中返回；llms.txt 的 Pages 部分将 tagline 输出为产品链接后的描述；前端产品卡片展示此字段。
标准填写规范
10-30 字，用一句话说明产品的核心价值和目标场景。例如"为中小制造企业打造的轻量化生产管理系统"。避免空泛的形容词堆砌。
错误后果
留空时 AI 从 description 中自行提取可能不准确；过长失去一句话定位的效果；与实际产品功能不符会误导用户预期。
description / content text 选填
设计初衷
description 是产品概述（用于列表页和 SEO 描述回退），content 是产品详情正文（用于详情页展示和 AI 语料）。
作用原理
description 写入 Product schema 的 description 字段和 og:description；content 通过 API 返回给前端渲染为产品详情页正文。
标准填写规范
description：50-100 字，概括产品功能、目标用户和核心价值。content：500-2000 字，包含产品概述、核心功能、技术架构、适用场景、对比优势。使用结构化分段（H2/H3）。
错误后果
description 留空时 SEO 描述回退到 content 首段可能不理想；content 过短（<200 字）的产品页被搜索引擎判定为薄内容。
features / specifications json 选填 GEO
设计初衷
features 是产品功能列表（JSON 数组），specifications 是技术规格参数（JSON 键值对）。两者作为产品事实数据输出给 AI。
作用原理
通过 API 返回给前端渲染为功能列表和规格表；Product schema 的 additionalProperty 字段可包含规格数据；AI 抓取时这些结构化数据是回答"XX 产品有哪些功能""XX 产品规格参数"的直接来源。
标准填写规范
features 格式：[{"title":"功能名","description":"功能说明"},...]，5-15 个功能点。specifications 格式：{"部署方式":"云端/私有化","并发用户":"500+","数据存储":"MySQL/PostgreSQL",...}，包含关键技术参数。数据必须与实际产品一致。
错误后果
规格数据与实际不符会导致用户投诉和信任度下降；AI 引用错误规格会传播错误信息；留空会让 AI 无法回答产品参数相关问题。

设计初衷
产品价格、货币类型和库存状态。这三个字段共同构成 Product schema 中的 Offer 对象，直接影响购物搜索展示和 AI 产品推荐。
作用原理
price 写入 Offer.price；currency 写入 Offer.priceCurrency（默认 CNY）；availability 写入 Offer.availability（映射为 schema.org URL）。Google 购物搜索抓取这些数据展示在结果中。
标准填写规范
price：填写产品的公开标价（非谈判价），无公开定价的填 0 或留空。currency：CNY（人民币）或 USD（美元）等 ISO 4217 货币代码。availability：在售选 in_stock，停产选 out_of_stock，预售选 pre_order。
错误后果
填写谈判价格泄露定价策略；价格与实际不符引发用户投诉；availability 与实际不符导致搜索引擎展示错误库存信息；不填价格时购物搜索无法展示产品。

设计初衷
价格区间和计价单位。用于无固定价格的产品（如定制化方案、按需计费服务）。
作用原理
priceRange 写入 Product schema 的 offers.priceRange 或作为页面展示文本；priceUnit 说明计价方式（如"元/年""元/用户/月"）。
标准填写规范
priceRange 格式："5万-20万"或"￥1,000-￥5,000/月"。priceUnit："元/年""元/用户/月""元/次"等。与 price 字段二选一使用。
错误后果
priceRange 与实际报价差距过大会误导用户；priceUnit 不明确导致用户对价格理解错误。
cases relation → case (manyToMany) 选填
设计初衷

作用原理
双向关联：产品页通过 API 返回关联案例列表；案例页也展示关联产品。知识图谱通过此关联建立 Product-CaseStudy 关系。

错误后果
不关联案例的产品页缺乏社会证明，转化率低；关联不相关案例会误导用户预期。

设计初衷

同文章 SEO 字段。产品页 SEO 错误的代价更高，因为产品页是转化入口。

第四章落地案例

4.1 设计目的与 GEO 角色

落地案例是官网信任建设的核心内容。它的设计目的是通过真实的客户故事和量化成果，向潜在客户和 AI 模型提供社会证明——证明你的产品/方案在真实场景中有效。

在 GEO 体系中，案例承担三个角色：可信度背书（CaseStudy 结构化数据向 AI 声明"这不是广告，是真实案例"）、长尾场景入口（通过"XX 行业 XX 问题解决方案"类长尾搜索获取流量）、产品页转化支撑（与产品双向关联，在产品页展示增强说服力）。

不做案例发布的后果：产品页缺乏社会证明，转化率下降 40-60%；AI 在回答"XX 公司的客户案例""XX 行业有没有成功案例"时找不到你的信息；竞品有案例而你没有，在对比中被淘汰。正确使用的效果：案例页通过"行业+问题+方案"长尾词获取精准流量，案例中的客户名和量化数据增强 AI 引用可信度。

5.4 字段四件套详解

title / description string / text title 必填 SEO GEO
设计初衷
教程标题和描述。标题应包含"怎么做""操作指南"等 HowTo 类关键词，描述概括教程目标和适用场景。
作用原理
title 写入 HowTo schema 的 name 字段和 <h1>；description 写入 HowTo schema 的 description 和 og:description；llms.txt 使用 title 和 description 作为教程链接的描述。
标准填写规范
title 格式："如何[完成某任务]"或"[产品名] [操作] 完整指南"。15-35 字。description：50-150 字，说明教程目标、适用版本和难度。例如"本教程指导你如何在 30 分钟内完成 MES 系统的初始配置，适用于 v3.0 以上版本。"
错误后果
标题不含"如何/怎么做"等 HowTo 关键词无法匹配 HowTo 搜索；description 不含适用版本信息导致用户按过时教程操作出错。
steps json 必填 GEO
设计初衷
教程操作步骤，以 JSON 数组格式存储。这是 HowTo 结构化数据的核心，也是 AI 引用教程时的直接数据来源。
作用原理
前端渲染为分步展示；HowTo schema 将每个步骤转为 HowToStep 对象（含 name、text、image）；Google 搜索结果可能展示前 3-5 步的富媒体片段。
标准填写规范
JSON 数组格式：[{"name":"步骤标题","text":"详细操作说明","image":"步骤截图URL"},...]。3-15 个步骤。每个步骤的 name 控制在 5-15 字，text 控制在 50-200 字。步骤顺序必须是可执行的操作顺序。
错误后果
JSON 格式错误导致前端渲染异常和 HowTo schema 失效；步骤缺失关键操作导致用户卡住；步骤顺序混乱导致操作失败；无截图的步骤在搜索结果中展示效果差。
videoUrl / thumbnailUrl string 选填 SEO
设计初衷
教程视频 URL 和缩略图 URL。填写后生成 VideoObject 结构化数据，让视频进入 Google 视频搜索索引。
作用原理
videoUrl 写入 VideoObject.contentUrl；thumbnailUrl 写入 VideoObject.thumbnailUrl。Google 视频搜索抓取这些数据后在视频搜索结果中展示缩略图和链接。
标准填写规范
videoUrl：填写视频的公开访问 URL（支持 MP4 直链或 YouTube/B 站嵌入链接）。thumbnailUrl：填写视频缩略图 URL，尺寸 1280x720px，JPG/WebP 格式。两个字段需同时填写。
错误后果
videoUrl 不可访问导致 Google 视频索引失败；只填 videoUrl 不填 thumbnailUrl 导致视频搜索结果无缩略图；URL 指向需要登录才能访问的视频会被搜索引擎跳过。
difficulty enumeration 选填
设计初衷
教程难度等级（入门/中级/高级），帮助用户选择适合自己水平的教程，同时让 AI 在推荐教程时考虑用户水平。
作用原理
前端展示难度标签；教程列表按难度筛选；AI 抓取时通过难度标签理解教程的目标受众。
标准填写规范
beginner：零基础可操作的基础教程。intermediate：需要一定产品使用经验的进阶教程。advanced：面向管理员或开发者的深度教程。根据教程实际需要的先决知识选择。
错误后果
难度标记过低导致新手尝试后失败，体验差；难度标记过高吓退目标用户。
materials / estimatedTime / result json / string / text 选填
设计初衷
materials 是教程所需素材清单（JSON），estimatedTime 是预计完成时间，result 是教程完成后的预期结果描述。三者共同构成 HowTo schema 的补充信息。
作用原理
materials 写入 HowTo.supply；estimatedTime 写入 HowTo.totalTime（ISO 8601 格式）；result 在教程末尾展示并写入 HowTo schema 的 expected结果描述。
标准填写规范
materials 格式：["账号权限","测试数据","操作手册PDF"]。estimatedTime 格式："30分钟"或"PT30M"（ISO 8601）。result：50-100 字描述完成教程后的状态，例如"完成本教程后，你将拥有一个配置完整的生产管理系统，可以开始录入生产订单。"
错误后果
materials 不完整导致用户中途缺少素材无法继续；estimatedTime 与实际差距过大影响用户预期管理；result 不明确让用户不确定教程是否完成。

第六章常见问答

6.1 设计目的与 GEO 角色

常见问答是 GEO 体系中与 AI 对话最直接对接的内容类型。它的设计目的是以问答对的形式直接匹配用户的提问——当用户向搜索引擎或 AI 提问时，FAQ 的问答对是最容易被直接引用的内容格式。

在 GEO 体系中，FAQ 承担三个角色：AI 问答直接匹配源（FAQPage 结构化数据中的每个问答对都可能被 AI 直接引用为回答）、语音搜索匹配（FAQ 的自然语言问句格式与语音搜索查询高度匹配）、客服成本降低（常见问题集中展示，减少重复咨询）。

不做 FAQ 的后果：AI 在回答用户关于你产品/企业的问题时使用第三方信息或不回答；语音搜索中完全不出现你的内容；客服重复回答相同问题消耗资源。正确使用的效果：FAQPage 结构化数据被 Google 收录后可在搜索结果中展示 FAQ 富媒体片段（直接展示问答内容），AI 模型在回答相关问题时直接引用你的官方回答。

6.4 字段四件套详解

question text 必填 SEO GEO
设计初衷
FAQ 的问题文本。应使用用户自然提问的语言，而非产品文档中的正式术语。这是 AI 匹配用户查询的第一信号。
作用原理
写入 FAQPage schema 的 Question.name 字段；作为 FAQ 页面的 <h2> 标题；llms.txt 输出为"FAQ: [question]"格式。搜索引擎和 AI 使用问题文本匹配用户查询。
标准填写规范
使用用户口语化的提问方式。例如"你们的系统支持多语言吗？"而非"系统多语言支持能力说明"。10-40 字。一个问题只问一件事。避免使用内部术语。
错误后果
使用正式术语而非用户语言导致无法匹配搜索查询；一个问题包含多个子问题导致 AI 无法精确匹配；问题过长影响搜索展示效果。
answer text 必填 SEO GEO
设计初衷
FAQ 的回答文本。应直接、简洁地回答问题，这是 AI 和搜索引擎直接展示给用户的内容。
作用原理
写入 FAQPage schema 的 Answer.text 字段；Google 搜索结果 FAQ 富媒体片段直接展示此文本；AI 引用时直接使用此文本作为回答。
标准填写规范
50-200 字。先给出直接答案（是/否/数字），再补充必要说明。避免营销话术。避免"请联系客服"类的回避回答。如果答案需要操作步骤，简要概括并链接到教程。
错误后果
答案过长在搜索结果中被截断；含营销话术导致 Google 拒绝展示 FAQ 富媒体片段；答案不准确被 AI 传播错误信息；回避性回答损害用户体验。
slug / category / tags / order 混合 slug 必填
设计初衷
slug 生成 FAQ 页面 URL；category 分类（产品/价格/技术/服务等）；tags 跨内容关联；order 控制展示顺序。
作用原理
slug 基于 question 自动生成；category 用于 FAQ 页面的分组展示；tags 通过标签索引与其他内容类型关联；order 控制同分类 FAQ 的展示顺序（小的在前）。
标准填写规范
slug：全小写英文，如 support-multi-language。category：选择最相关的分类。tags：2-5 个关键词标签。order：重要 FAQ 设为 0-10，一般 FAQ 设为 50-100。
错误后果
slug 含中文导致 URL 不可读；不设 category 导致 FAQ 列表混乱；order 全部为 0 导致展示顺序随机。

第七章合规公示

7.1 设计目的与 GEO 角色

合规公示是官网法律合规和信任建设的底层支撑。它的设计目的是集中展示企业的法律资质、政策文件、合规报告和用户协议，向搜索引擎、AI 模型和用户声明企业的合规状态。

在 GEO 体系中，合规公示承担三个角色：合规信号源（通过结构化数据向 AI 声明企业的合规状态和法律资质）、信任锚点（ICP 备案、营业执照、资质证书等是 AI 评估企业可信度的参考因素）、法律风险隔离（用户协议、隐私政策等公示内容是法律合规的要件）。

不做合规公示的后果：AI 模型在评估企业可信度时缺少合规信号，可能将企业标记为"信息不完整"；用户无法找到隐私政策和用户协议，法律风险增加；搜索引擎对缺少合规信息的站点降低信任评分。正确使用的效果：合规信息通过结构化数据输出，增强 AI 对企业合法性的认知；用户协议和隐私政策公示满足法律合规要求。

7.4 字段四件套详解

title / content string / text 必填
设计初衷
合规文件标题和正文内容。标题应明确文件类型和主题，正文为法律文件的完整文本。
作用原理
title 写入 <h1> 和结构化数据；content 通过 API 返回前端渲染为合规文件页面；llms.txt 将合规文件链接输出到 Pages 部分。
标准填写规范
title 格式："[文件类型] - [文件主题]"，如"用户协议 - 智造云平台服务条款"。content：法律文件完整文本，使用 HTML 或 Markdown 格式。包含版本号、生效日期、条款内容。
错误后果
内容不完整或与实际法律文件不符可能导致法律纠纷；过时的协议版本可能导致条款无效。
category enumeration 必填
设计初衷
合规文件分类，区分不同类型的公示文件。影响前端展示分组和 AI 分类理解。
作用原理
枚举值：notice（公告）、policy（政策）、report（报告）、certificate（证书）、agreement（协议）。前端按分类分组展示。
标准填写规范
notice：临时性公告（如系统维护通知）。policy：企业政策（如隐私政策、 Cookie 政策）。report：合规报告（如年度合规报告）。certificate：资质证书（如营业执照、ICP 备案）。agreement：用户协议（如服务条款、用户协议）。
错误后果
分类错误导致文件出现在错误的公示分组中；用户协议被分类为公告可能被用户忽略。
effectiveDate / expiryDate date / date 选填
设计初衷
合规文件的生效日期和失效日期。用于管理文件的有效期和提醒更新。
作用原理
前端展示文件有效期；过期的协议文件前端标注"已更新"；管理后台可按到期日排序提醒更新。
标准填写规范
effectiveDate：文件正式生效的日期。expiryDate：文件失效日期（长期有效的留空）。日期格式 YYYY-MM-DD。
错误后果
生效日期填写错误可能导致协议在过渡期无效；未设置 expiryDate 的临时公告长期展示在页面上。
isPinned boolean / default:false 选填
设计初衷
置顶开关。将重要合规文件（如用户协议、隐私政策）固定在列表顶部。
作用原理
前端合规列表页将 isPinned=true 的文件排在最前面展示。
标准填写规范
用户协议、隐私政策等核心文件设为 true。临时公告和报告设为 false。
错误后果
过多文件设为置顶导致置顶功能失效；核心协议未置顶可能被用户忽略。

7.5 标准发布全流程

素材准备

素材要求用途
法务文件文本完整法律文件，经法务审核填入 content
生效日期法务确认的生效日填入 effectiveDate
资质证书图片（如有）扫描件, 清晰可读嵌入 content 中

填写顺序

  1. 基础信息 — 填写 title、slug、content（法律文件全文）
  2. 分类 — 选择 category（notice/policy/report/certificate/agreement）
  3. 有效期 — 填写 effectiveDate 和 expiryDate（如有）
  4. 置顶 — 核心文件设 isPinned=true
  5. SEO — 填写 seoTitle 和 seoDescription
  6. 收录控制 — allowIndex：公开文件设 true，内部文件设 false
  7. 法务审核 — 提交法务负责人审核确认
  8. 发布 — status 改为 published

发布前自检清单

  • title 明确文件类型和主题
  • content 为法务审核通过的完整文本
  • category 分类正确
  • effectiveDate 已填写
  • 核心文件 isPinned=true
  • 法务负责人已审核确认
  • allowIndex 设置正确（公开/内部）
  • 如为证书类，证书图片清晰可读

7.6 发布后闭环运作与禁忌

前端展示与 GEO 效果

合规公示发布后，前端合规页面按分类分组展示所有文件。核心协议（用户协议、隐私政策）置顶展示。合规信息通过 sitemap 和 llms.txt 输出，AI 模型在评估企业合法性时可参考公示的资质和法律文件。ICP 备案号同时通过 seo-config 写入页面底部全局展示。

更新机制

合规文件更新操作规范

用户协议或隐私政策更新时：创建新版本（新记录），将旧版本 status 改为 archived 并设置 expiryDate 为新版本生效日前一天。新版本设 isPinned=true。不要直接修改已发布的旧版本内容——保留历史版本用于法律追溯。

内容禁忌类型

禁止发布的合规内容

1. 未经法务审核的文件 — 未经法务审核的法律文件。后果：可能包含无效条款或法律漏洞，面临法律风险。

2. 过时的协议版本 — 协议已更新但旧版本未归档。后果：用户可能引用过时条款产生纠纷。

3. 敏感信息泄露 — 公示文件中包含商业机密或客户信息。后果：商业损失，可能面临法律赔偿。

4. 营销化表述 — 在法律文件中使用营销话术。后果：法律文件失去法律效力，可能被法院判定为无效。

5. 缺失核心条款 — 用户协议缺失免责条款、争议解决条款等。后果：法律纠纷时缺乏条款保护。

questionanswer
你们平台的采购流程是什么？B2B 采购流程为：注册企业账号 → 完善企业资质 → 浏览商品或发布采购需求 → 在线下单或发起询价 → 供应商确认 → 签署电子合同 → 支付担保交易 → 验收收货。全流程通常 3-7 个工作日。
支持哪些支付方式？支持企业对公转账、银行承兑汇票、担保交易和账期付款。新客户默认担保交易（货到验收后付款），合作 6 个月以上的企业客户可申请 30-60 天账期。
最低起订量是多少？不同商品起订量不同，一般在商品详情页标注。工业标准件通常 1 件起订，定制件起订量根据供应商要求设定。大宗采购可联系客服协商。
发票怎么开？支持增值税专用发票和普通发票。下单时填写开票信息，收货后 3 个工作日内开具电子发票发送至注册邮箱。纸质发票可申请邮寄，包邮。
退换货政策是什么？标准件 7 天无理由退换（不影响二次销售）。定制件非质量问题不支持退换。质量问题 30 天内免费退换，运费由平台承担。
