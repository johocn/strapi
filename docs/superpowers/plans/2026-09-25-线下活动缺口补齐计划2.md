### Task A: 改期/取消群发通知（zhao-point）

**Files:**
- Create: `plugins/zhao-point/server/src/services/activity-notice.ts`（纯逻辑）
- Modify: `plugins/zhao-point/server/src/controllers/activity.ts`（adminUpdate 路径 ~L597-645）、`plugins/zhao-point/server/src/services/activity.ts`（供群发的轻量包装）
- Test: `plugins/zhao-point/tests/activity-notice.test.ts`

**设计决策：**
1. 触发点唯一：`adminUpdate`（管理端编辑活动）。检测两处变化：① `startTime`/`endTime` 变化 → 改期通知；② `status` 变为 `cancelled`（若 status 枚举含 cancelled）或活动被 unpublish → 取消通知。下架（published_at 置空）按取消处理。
2. 收件人 = 该活动 `status IN (active, waiting)` 的报名用户集合（去重）。
3. 站内信循环逐人 `notifyInApp`，幂等 key：改期 `activity:rescheduled:${userId}:${actId}`、取消 `activity:cancelled:${userId}:${actId}`。微信走既有模板机制，模板缺失只 warn 不阻断（通知失败不回滚活动编辑）。
4. 纯函数 `detectStatusChange(oldAct, newAct)` 返回 `{ kind: "rescheduled" | "cancelled" | "none", changedFields: string[] }`——单测覆盖：时间变化/状态变化/两者同时/无变化/新活动（无 old 返回 none）。

- [ ] **Step A1: 写失败单测**（detectStatusChange 五个用例 + 收件人过滤规则纯函数 `audienceFor` 若抽取）
- [ ] **Step A2: 实现纯函数与接线**：adminUpdate 在事务/更新成功后调用群发（群发放更新主流程之后、失败只 warn）
- [ ] **Step A3: `npm test` 全绿（permissions 21 例既有失败除外）→ `npm run build` → Grep dist 含 `rescheduled` → commit（只 add 本 Task 文件+dist）→ push → ff-only 部署 → `pm2 restart` → 日志验证
- [ ] **Step A4: 验证**：生产改任一测试活动时间，C 端已报名测试用户收到改期站内信；恢复原时间不再群发（幂等 key 生效）
