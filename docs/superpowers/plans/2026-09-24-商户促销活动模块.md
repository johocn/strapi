# 商户促销活动模块 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在现有 `activity` 模型上落地第三类活动「商户促销活动」——新增 `goods`/`purpose`/`notice` 三个宣传模块、场地一键导航与四项营销能力，全程不新建 content-type、不接商城 SKU、不做线上抵扣。

**Architecture:** 数据层复用 `activity`，仅新增 `goodsList`(json) / `purpose`(text) 两列并给 `promoTemplate` 约定值加 `sale`；契约层是「模块类型白名单 ↔ 各渲染分发处 ↔ 组件文件」的一致性，由三个仓库各自的契约测试锁死；营销四项全部为既有能力的薄接线（报名扫码核销 / 分享海报 / activity-stats 看板），不引入新表与新服务。

**Tech Stack:** Strapi 5 插件 `zhao-point`（TS）、uni-app Vue3 管理端 `web`、uni-app Vue3 C 端 `shao`、Node 20 内置 `node:test`（web / basic 零依赖测试）、`jest@29 + ts-jest`（shao 既有单测）、SCSS 主题变量。

## 与设计文档的偏差纠正（先读这一节）

### 纠正 1：同步点不是「三处」，实际是 7 处

设计文档 §5.1 写「三处同步契约」，实测遗漏 4 处，漏任一处 C 端都会静默不渲染：

| # | 位置 | 说明 |
|---|---|---|
| 1 | `web/src/pages/activity/promo-import.js` `PROMO_MODULE_TYPES`(L6) + `normalizeModuleConfig`(L31) | AI 导入白名单与归一化 |
| 2 | `web/src/pages/activity/promo-presets.js` `PROMO_MODULE_META` | 模块展示名/是否需配置 |
| 3 | `web/src/pages/activity/promo.vue` 配置面板(L116-224) + 预览分发(L370-391) | 运营端配置与预览 |
| 4 | `web/src/components/promo/promo-*.vue` | 运营端预览组件（C 端副本） |
| 5 | `shao/components/promo/promo-*.vue` | C 端真实组件 |
| 6 | `shao/pages/activity/promo.vue` `PROMO_TYPE_SET`(L277-291) + 分发(L11-38) | C 端宣传页**
| 7 | `shao/pages/activity/detail.vue` `PROMO_TYPE_SET`(L1443) + 分发(L65-91) | C 端详情页 |
| 8 | **后端** `basic/plugins/zhao-point/server/src/services/activity.ts` `PROMO_MODULE_TYPES`(L12-15) | 服务端 `normalizePromoModules` 会过滤类型，白名单不含新类型则 C 端永远收不到该模块 |

> 第 8 项是设计文档完全没写的硬伤：`promoDetail` 返回的 `modules` 经过 `normalizePromoModules` 过滤（`services/activity.ts:90`），controller 内的同名函数（`controllers/activity.ts:94`）复用同一常量，因此**只需改 `services/activity.ts` 的常量**，两处同时生效。

### 纠正 2：`promoTemplate` 目前没有任何选择 UI

全仓库 `promoTemplate` 只在 `web/src/pages/activity/promo.vue` 与 `form.vue` 里作为默认值 `'summit'` 与保存字段出现，**没有选择器**。设计文档 §4 说「前端按该值切换默认模块集」需要补 UI，故本计划新增 `sale` 模板选择器 + 促销默认模块集。

### 纠正 3：`promoTemplate` 相关还有 3 处同步

`PROMO_TEMPLATES`（后端 `services/activity.ts:18`，不含 `sale` 会被 controller 以「promoTemplate 非法」拒绝）、`web/src/styles/promo-themes.scss`、`shao/styles/promo-themes.scss` 都需加 `sale`，否则页面无配色变量（`--c-*` 全空）。

### 纠正 4：既有白名单本就不一致（本计划保持现状并显式锁定）

- `web` 白名单 12 类，缺 `floatContact`（仅 AI 导入用途，C 端才有持久化必要）
- `shao` 两个页面白名单 13 类 = web 12 + `floatContact`
- 后端 13 类，与 shao 一致
- `PROMO_MODULE_META` 有 14 键（含 `tour`），`tour` 不在任何白名单里

本计划新增 3 类后：**web 15 类 / shao 16 类 / 后端 16 类**，并把这组数字写进各仓库契约测试，不再放任漂移。

### 纠正 5：测试设施的真实状态

- `web`：`package.json` 无 `test` 脚本、无任何测试依赖。Node 20.19 会「检测到 ESM 语法后自动重解析为 ES module」，因此 **`.mjs` 测试文件可以直接 `import` `promo-import.js`**，实测可行，无需新增依赖（见 Task 3 的验证命令）。
- `shao`：`package.json` 声明了 `jest@^29.7.0 + ts-jest`，但 `node_modules` 中**并未安装**，且 `jest.unit.config.js` 因根 `tsconfig.json` 的 `types: ["@dcloudio/types"]` 覆盖了 jest 全局类型，导致**所有单测都报 `Cannot find name 'expect'`**。`npm install` 还会因 `@dcloudio/uni-automator` 的 `jest@27.0.4` peer 冲突失败。Task 11 修复。
- `.vue` SFC 在 `shao` 的 jest 下**无法被 import**（无 `vue-jest`、无 `.vue` 类型声明）。因此组件不写渲染单测，改为「纯函数放 `utils/*.ts` 做单测 + 组件与分发由契约测试锁死」。
- `basic`：无测试框架、无 `test` 脚本，同样用 `node --test`。

- [ ] **Step 4: 最小实现：`normalizeGoodsList`**

在 `normalizePromoModules` 之前（原第 57 行后）插入：

```js
// 归一化促销商品清单：丢弃非对象项与「原价/促销价皆缺」的项；单侧有价则单侧展示
export function normalizeGoodsList(raw) {
  if (!Array.isArray(raw)) return []
  const toPrice = v => {
    if (v === undefined || v === null || v === '') return null
    const n = Number(v)
    return Number.isFinite(n) && n >= 0 ? n : null
  }
  const out = []
```

```ts
// 商户促销活动 —— 商品清单归一化与价格文案（纯函数，供 promo-goods.vue 使用）

export interface PromoGood {
  name: string
  image: string
  originPrice: number | null
  promoPrice: number | null
  unit: string
  limitPerPerson: number | null
  desc: string
}

/** 价格归一：空/非数字/负数 → null（表示该侧不展示） */
function toPrice(v: any): number | null {
  if (v === undefined || v === null || v === '') return null
  const n = Number(v)
  return Number.isFinite(n) && n >= 0 ? n : null
}

/** 归一化商品清单：丢弃非对象项与「原价/促销价皆缺」的项 */
export function normalizeGoodsList(raw: any): PromoGood[] {
  if (!Array.isArray(raw)) return []
  const out: PromoGood[] = []
  for (const it of raw) {
    if (!it || typeof it !== 'object' || Array.isArray(it)) continue
    const originPrice = toPrice(it.originPrice)
    const promoPrice = toPrice(it.promoPrice)
    if (originPrice === null && promoPrice === null) continue
    out.push({
      name: typeof it.name === 'string' ? it.name.trim() : '',
      image: typeof it.image === 'string' ? it.image : '',
      originPrice,
      promoPrice,
      unit: typeof it.unit === 'string' ? it.unit.trim() : '',
      limitPerPerson: toPrice(it.limitPerPerson),
      desc: typeof it.desc === 'string' ? it.desc.trim() : '',
    })
  }
  return out
}

/** 价格文案：origin 为划线原价，promo 为促销价；缺值为空串 */
export function goodsPriceText(g: Pick<PromoGood, 'originPrice' | 'promoPrice'>): { origin: string; promo: string } {
  return {
    origin: g.originPrice == null ? '' : `¥${g.originPrice}`,
    promo: g.promoPrice == null ? '' : `¥${g.promoPrice}`,
  }
}
```

```ts
// 商户促销活动 —— 稀缺转化计算（纯函数，供 promo-scarcity.vue 使用）

export interface ScarcityInput {
  startTime?: string
  endTime?: string
  capacity?: number | null
  usedCapacity?: number | null
}

export interface ScarcityState {
  visible: boolean
  ended: boolean
  soldOut: boolean
  remaining: number
  progress: number
  used: number
  capacity: number
  countdown: string
}

/** 毫秒 → 「2天03:04:05」/「03:04:05」；<=0 返回 00:00:00 */
export function formatCountdown(ms: number): string {
  const total = Math.max(0, Math.floor(ms / 1000))
  const days = Math.floor(total / 86400)
  const h = Math.floor((total % 86400) / 3600)
  const m = Math.floor((total % 3600) / 60)
  const s = total % 60
  const pad = (n: number) => String(n).padStart(2, '0')
  const hms = `${pad(h)}:${pad(m)}:${pad(s)}`
  return days > 0 ? `${days}天${hms}` : hms
}

/** 名额已满或活动已结束 → visible=false（不输出空壳） */
export function computeScarcity(input: ScarcityInput, now: number = Date.now()): ScarcityState {
  const capacity = Number(input.capacity) > 0 ? Number(input.capacity) : 0
  const used = Number(input.usedCapacity) > 0 ? Number(input.usedCapacity) : 0
  const remaining = capacity > 0 ? Math.max(0, capacity - used) : 0
  const progress = capacity > 0 ? Math.min(100, Math.max(0, Math.round((used / capacity) * 100))) : 0

  const endMs = input.endTime ? new Date(input.endTime).getTime() : NaN
  const hasEnd = Number.isFinite(endMs)
  const ended = hasEnd ? endMs <= now : false
  const soldOut = capacity > 0 && used >= capacity

  const started = input.startTime ? new Date(input.startTime).getTime() : NaN
  const notStarted = Number.isFinite(started) && started > now

  const hasCountdown = hasEnd && !ended
  const visible = !ended && !soldOut && (hasCountdown || capacity > 0 || notStarted)

  return {
    visible,
    ended,
    soldOut,
    remaining,
    progress,
    used,
    capacity,
    countdown: hasCountdown ? formatCountdown(endMs - now) : '',
  }
}
```
