> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 修掉活动域 14 项已核实缺陷，按 3 批交付：非 admin 角色可用活动域 + 活动/剧本游积分能真正发放（批 1）；活动关闭入口可达、列表不再静默丢数据（批 2）；状态与口径一致性收口（批 3）。

### Task 5: `adminList` 支持过滤 + 返回总数

**背景**：现在 `adminList` 把 `.filter` 之外的 query 全部 spread 进 `findMany`，但 `filters` 在 spread **之后**被显式赋值覆盖 → 前端经 `filters[title]` 传的过滤永远被丢掉。同时因为用的是 `findMany`（返回数组、无分页元信息），前端拿不到总数，只能 `pageSize:500` 拉全量、在客户端切片，活动超 500 条静默丢数据。

#### 根因：三道门，门 3（`has-tenant-access`）是决定性瓶颈

`channelScopeRoute` = `is-authenticated` → `has-permission` → `has-channel-scope` → `has-tenant-access`。实测（用户 id=1，非 admin）：

| 门 | 判定点 | 实测 | 说明 |
|---|---|---|---|
| 1 | `has-permission`(`activity.read`) | ✗ | `channel-admin` 266 条权限码中活动相关 **0 条**；`point-manager` 43 条同样为 0 → 既有角色都需重勾 |
| 2 | `has-channel-scope` | ✗ | id=1 无任何渠道归属（`zhao_user_channels` / `zhao_channel_members` / `zhao_role_channels` 均无其记录） |
| 3 | `has-tenant-access` | ✗ | **站点侧渠道集合恒为空** |

**门 3 的数据事实（决定性）**：`zhao_site_configs` 仅 3 条（id=1 `joho.cn`、id=2 `圣麟口腔 www.shenglin.vip`、id=3 `锦润学域 v.joho.cn`）；`zhao_channels_sites_lnk` 仅 2 行 —— **只有 site 2/3 ↔ channel 2，site 1 无任何渠道关联**。管理端域名 `h.joho.cn` 不匹配任何 `site.domain`（日志 `[site-resolver] domain "h.joho.cn" 未匹配，回退到默认站点`）→ 回退到 id 最小站点（id=1）→ `siteChannelIds=[]` → `has-tenant-access` 直接 return false → 403。

**这解释了「先授渠道 / 先分角色」两种顺序都试不通**：站点侧渠道集合恒为空，用户侧配得再全也没有交集。

#### 运营操作指引（三步缺一不可）

1. **给站点关联渠道**（决定性一步）：CMS → 站点配置 → `joho.cn`(id=1) → 渠道，关联 `平台根渠道`(id=1) 或 channel 2。管理端固定解析到该站点（域名不匹配 → 回退 id 最小站点），不关联则永远 403。
2. **角色页重勾「活动中心」父节点**：级联写入 14 条权限码。既有角色活动权限全为 0，必须重勾。
3. **给账号授渠道**：B3 已修复并上线，三种方式（用户级 / 角色级 / 渠道成员）均可。
   - 补充结构性原因：管理端登录 `adminLocal` **不调用** `ensureDefaultChannel`（仅 C 端 `register`/`login` 补默认渠道），故管理端非 admin 账号天生无渠道，必须显式授渠道。
   - `site-resolver` 会兜底取最小 id 站点，`siteId` 恒有值，**不会**走「未识别租户放行」分支。
