# 在地·剧本游 —— 本地文化旅游报名（半日主题线）设计

> 日期：2026-09-03
> 决策依据：在现有「活动」系统闭环之上，开发本地文化旅游报名功能，复用活动完整闭环，叠加线路/文化/沉浸/游戏化。

## 1. 背景与目标

现有 `activity` 已具备完整闭环：报名流程（登录→奖励→信息→报名）、积分发放、关注公众号/问卷解锁奖励、候补、分享裂变（海报+分享得积分+邀请码归因）、到场二维码核销/签到、活动后评价/回放/复购/未到场回访（手动 SOP 待办）、系列活动与快照。

传统旅游「走马观花」，本次目标为**走马观花 → 沉浸+快乐**：把本地文化体验做成一部可进入的剧，用户在游程中扮演角色、解谜、打卡、做非遗手作，通关拿徽章与积分，形成与活动一致的闭环营销。

## 2. 产品锚点（已与用户逐项确认）

| 维度 | 定案 |
|---|---|
| 目标客群 | 大众文化体验（通吃；本地居民/家庭/社交/游客，门槛低） |
| 体验主轴 | 剧情任务向：整条线路=剧本/寻宝/解谜，游客当角色，打卡+答题+互动兑奖 |
| 游程形态 | 半日主题线：1 条老街/1 个片区，2–4h，5–8 任务点，线上剧本+线下自引导（关键点配在地主理人） |
| 精准营销切入点 | 内容兴趣标签（报名表单/问卷采集，公众号画像辅助），按标签圈选触达 |
| 变现模型 | 引流+现场衍生：报名低价/免费攒人气，现场手作成品/文创/餐饮衍生变现，积分+分享激励拉复购 |
| 落地方式 | 方案 A：扩展活动 + 轻量「旅游剧目」配置，C 端叠加沉浸剧本层 |

## 3. 定位与价值主张

**把一条老街，变成一部可进入的剧。** 用户 2–4 小时微游程里扮演当地角色（书生/账房/绣娘学徒），边走边解谜、打卡、做非遗手作，通关拿徽章与积分——从「走过的游客」变成「故事里的人」。

反走马观花的三条机制：
- **任务式沉浸**：带着目的去看门楣/戏台/石桥/老字号，而非扫一眼。
- **角色与剧情**：情感卷入，愿意为其停留与完成。
- **即时正反馈**：打卡/答题/徽章/积分随时给奖励。

## 4. 线路与内容设计

### 4.1 主题线（剧目）样例
首期 1–2 条：「老街寻宝记」「运河边的老手艺人」「非遗半日·跟着手艺走街」。
主题线按季轮换保持新鲜，周末黄金时段发团。

### 4.2 六段式内容骨架
1. **序章**：集合点领「身份卡」，扫码进入线上剧情，选择角色。
2. **7 个任务点**：每站 = 1 文化线索（老字号门脸/戏台/石桥/老宅）+ 1 互动类型（解谜答题/找细节计数/听故事填空/与店主对暗号/拍照构图打卡/集邮盖章）。
3. **手作参与彩蛋 1–2 站**：非遗手作或在地小吃，产出可带走作品（= 现场衍生变现点，MVP 靠主理人现场完成）。
4. **主线解谜**：7 站线索拼出「旧城谜底」，答对解锁终极关卡。
5. **终章兑奖**：集齐徽章/达标积分 → 兑换文创/纪念章/下条线路优惠券/积分。
6. **留住彩蛋**：方言祝福、合影框、下条线路悬念预告。

### 4.3 领队 / NPC
MVP 以「线上剧本 + 线下自引导」为主（省人力）。手作站/终章配 1 名在地主理人或店主当「NPC/印章守护者」，兼任现场衍生销售。

## 5. 沉浸式游戏机制

- **身份卡 + 剧情线**：线上 H5 承接角色选择、进度、答对/答错反馈、轻量剧情分支（非重型 RPG）。
- **到点打卡 = 复用到场核销**：任务点映射为活动 checkpoint，每次打卡成功 = 一次核销事件 + 发积分/徽章（复用 zhao-point 积分 + 到场核销 service）。
- **积分 + 徽章双重激励**：任务得分、完线徽章、手作分进 zhao-point 统一账，可抵扣下次线路/兑换文创；徽章为收藏向传播。
- **分享裂变**：复用分享海报 + ShareGuide 分享得积分 + 邀请码归因；终章解锁「组队邀请」彩蛋。
- **主题场/限时**：定时发团制造稀缺；线路按季轮换。

## 6. 精准营销与运营策略

### 6.1 精准圈人（内容兴趣标签）
- 报名即采集兴趣标签（非遗/手作/老街/亲子/在地美食/微旅行…）沉淀到用户画像；关注公众号时间与偏好做辅助画像。
- 新线路上线时按标签圈选人群，复用 zhao-sso 消息模板 / 手动 SOP 待办做定向触达。

### 6.2 用户生命周期
低价免费首游 → 玩中分享重组 → 徽章/积分留存 → 新线复游（标签匹配）→ 私域沉淀（关注公众号/加群），现场衍生拉高 AOV。

### 6.3 复购 / 回访闭环（复用活动后 manualSop 待办）
- 完线：自动生成「邀评价/晒图 + 下条线路预告」待办。
- 未到场：生成「改期/挽回」待办。

### 6.4 传播节奏
周末 + 文化热点期蹭热点；「组队邀请」裂变奖励冷却与分享得积分一致。

## 7. 技术落地（方案 A：扩展活动，复用闭环）

### 7.1 数据模型
扩展 `activity` 新增可选旅游字段组（为 null/关闭则在旅游维度上退化为普通活动）：
- `tourMode`：boolean，是否旅游剧目模式。
- `itinerary`：JSON 站点数组：{ name, clue(文化线索), interactType(解谜/计数/填空/暗号/拍照/集章), order, geo(可选坐标) }。
- `storyId` → 新轻量 content-type `tour-story`：{ title, backdrop, roles[], mainPuzzle, answer, finaleRewardConfig }。
- `checkpoint`：把 7 任务点映射到活动到场核销点。
- `guideId`：领队/NPC 关联（在地主理人/店主）。

### 7.2 C 端（活动推广页之上的沉浸剧本层）
选身份 → 按码走线打卡/答题 → 进度条/剧情反馈 → 终章兑奖。到点打卡调复用到场核销 service。

### 7.3 复用清单（新增最少）
报名流程、积分、分享裂变、到场核销、评价、回访/复购、消息模板/手动 SOP、抽奖。

### 7.4 运营端
admin 新增/扩展：剧目配置、站点/任务配置、终章兑奖配置；按兴趣标签圈选的定向触达入口。

### 7.5 卡点分析（规划期识别）
- **卡点1 · 打卡=核销的语义兼容**：任务点打卡与现有「到场核销」注册事件需统一，避免多算到场人数/积分。→ 设计按 `checkpoint` 唯一码承接，核销事件带任务点维度。
- **卡点2 · 剧情 H5 与活动闭环的联通**：剧本层的角色/任务态需与参与者的报名/积分记录对齐（同一用户、同一活动）。→ 剧本层挂在活动 participant 上下文中。
- **卡点3 · 标签采集度**：内容兴趣标签依赖报名表单/问卷，首期需在报名表单加兴趣字段，否则圈人无据。→ MVP 必含标签采集。
- **卡点4 · 现场衍生变现**：MVP 无法线上收单/核销，靠主理人现场进行。→ MVP 定义为线下衍生，P2 再线上化。
- **卡点5 · 领队人力**：全 NPC 化成本高。→ MVP 线上自引导 + 关键点主理人。

### 7.6 验收 / 成功指标（MVP）
- 一条半日主题线可上线运营：报名（含兴趣标签采集）、角色选择、7 站打卡+答题、主线谜底、终章兑奖、积分/徽章到账、分享裂变（海报+分享得积分+邀请码归因）、完线/未到场回访待办。
- 全链路复用活动闭环 service，新增 content-type 仅 `tour-story` 一个。
- C 端沉浸剧本层在推广页可进入，打卡核销不重复计人数/积分。

## 8. MVP 范围与分期

- **MVP（本期）**：方案 A + 1 条「老街寻宝记」半日线 + 线上剧本/7 站/主线谜底 + 积分徽章/分享裂变/到场打卡核销 + 标签采集与圈选触达；现场衍生走主理人。
- **P2**：一日深度线、组队邀请、限时主题场、奖励商城、现场衍生线上化。
- **P3**：模块拼装线、AR 打卡、多片区/商家入驻。

## 9. 风险与开放问题
- 首期剧本内容需运营/在地主理人共创文案，剧本质量直接决定口碑。
- 精准触达依赖标签沉淀量，冷启动期可能转化有限，需配合泛人群推广补位。
- 7.5 卡点2 的联通实现方式待实现计划阶段定稿。
