# 商户促销活动模块 — 设计文档

- 日期：2026-09-24
- 状态：设计已确认，待实施
- 关联仓库：`web`（uni-app 管理端 / C 端 H5）、`basic/plugins/zhao-point`（Strapi 插件）
- 上游：`docs/superpowers/specs/2026-08-26-activity-full-loop-design.md`

## 1. 背景与目标

现有活动能力以「活动讲座 / 旅游」两类为主，活动宣传页由 `activity.promoModules` 驱动渲染（模块类型固定 12 种）。本期新增第三类**商户促销活动**，以模块化方式承载活动时间、活动地点、促销商品内容及价格、活动目的、活动说明，并为活动场地增加地图导航，同时补充满足营销需要的整体功能。

目标：

1. 运营不写代码即可配置出完整的商户促销宣传页。
2. C 端用户能看清促销商品与价格、一键导航到店、领促销码到店核销。
3. 商户能通过看板看到促销的曝光与转化效果。

## 2. 范围

### 2.1 包含

- `activity` 模型新增促销字段。
- 新增 3 个宣传模块类型：`goods` / `purpose` / `notice`。
- `info` 模块的「一键导航」增强。
- `promoTemplate` 约定值新增 `sale`。
- 四项营销功能：稀缺转化组件、优惠券到店核销、海报分享裂变、营销数据看板。

### 2.2 不包含

- 促销商品关联商城 SKU、库存与线上订单。
- 线上支付 / 抵扣 / 结算（不涉 `zhao-deal`）。
- 多门店点位导航（本期仅单一场地）。
- 新建数据表（全部复用现有 content-type）。

## 3. 关键决策（已确认）

| 决策点 | 结论 |
|---|---|
| 数据模型 | 复用 `activity`，新增分类「商户促销」 |
| 商品来源 | 活动内手填清单，仅宣传展示 |
| 地图导航 | 一键导航到单一场地（`uni.openLocation`） |
| 营销功能 | 四项全部纳入 |
| 优惠券范围 | 仅到店核销，不做线上抵扣 |

## 4. 数据模型设计

文件：`basic/plugins/zhao-point/server/src/content-types/activity/schema.json`

新增字段：

- `goodsList`：`json`，元素结构 `{ name, image, originPrice, promoPrice, unit, limitPerPerson, desc }`
- `purpose`：`text`（活动目的）

改动：

- `promoTemplate` 仍为 `string`，约定值新增 `sale`；前端按该值切换默认模块集。

复用（不新增）：

- `description` → 活动说明
- `startTime` / `endTime` → 活动时间
- `venueName` / `lat` / `lng` / `meetupPoint` → 活动地点与导航
- `capacity` / `usedCapacity` → 稀缺转化条

分类：沿用 `category`（自由字符串 + picker 预设 + 快速新建），新增预设项「商户促销」。**不引入枚举**，保持现有自由分类不被破坏。

迁移：Strapi 启动时按 schema 自动同步新增 `json` / `text` 列（与既有 `promo*` 字段一致），无需手工 DDL。

## 5. 宣传模块设计

### 5.1 三处同步契约（硬约束）

模块类型是**契约**，必须三处同步，漏一处 C 端会静默不渲染：

1. `web/src/pages/activity/promo-import.js` — `PROMO_MODULE_TYPES` 加入 `goods` / `purpose` / `notice`；`normalizeModuleConfig` 增加对应分支。
2. `web/src/pages/activity/promo.vue` — 模块配置面板增加三种配置 UI；`PROMO_MODULE_META` 增加展示名。
3. `web/src/components/promo/` — 新增 `promo-goods.vue` / `promo-purpose.vue` / `promo-notice.vue`，并在 C 端渲染分发处注册。

### 5.2 模块定义

| 模块 | 数据源 | 渲染要点 |
|---|---|---|
| `goods` | `goodsList` | 商品卡：图、名称、原价（划线）、促销价、单位、限购、说明；`config.title` 可覆盖标题；底部固定「价格以到店为准」 |
| `purpose` | `purpose` | 活动目的段落；`config.title` 可覆盖标题 |
| `notice` | `description` + `config.html` | 活动说明 / 规则；`config.title` 可覆盖标题；正文与补充共存时正文在前 |

### 5.3 info 模块增强

时间 / 地点行内加「📍 一键导航」按钮，点击调用 `uni.openLocation({ latitude, longitude, name, address })`。

### 5.4 促销类默认模块序

`cover → goods → purpose → notice → info → contact`

## 6. C 端页面与导航

- 详情页维持按 `promoModules` 顺序渲染，新增模块走同一分发机制。
- 导航按钮仅在 `lat` / `lng` 有效（非空且非 0）时可用。
- 促销页顶部渲染稀缺转化条（见 7.1）。

## 7. 营销功能

### 7.1 稀缺转化组件

- 数据来源：`startTime` / `endTime`（倒计时）、`capacity` / `usedCapacity`（名额进度条与「已抢 X 件」）。
- 无新表；名额已满或活动结束后自动隐藏。

### 7.2 优惠券 + 到店核销

- 复用 `channel-verification` 与 `web/src/pages/activity/scan.vue`。
- C 端活动页发放促销码，门店店员用现有扫码核销。
- 仅到店核销，不做线上抵扣与结算。

### 7.3 海报分享裂变

- 复用 `zhao-studio` 的海报模板（`web/src/pages/studio/poster-template`）。
- 模板增加「促销商品 + 价格 + 二维码」取数。
- 分享得积分复用 `shareRewardPoints`；邀请助力复用 `web/src/pages/activity/fission.vue`。

### 7.4 营销数据看板

- 复用 `activity-stats` 与 `web/src/pages/activity/ledger.vue`。
- 促销视图呈现：曝光 / 浏览 / 报名 / 核销 / 转化漏斗。
- 浏览数据由 `zhao-track` 上报（覆盖情况见 11.3）。

## 8. 数据流

```
运营（web 管理端）
  form.vue  填活动基本信息 + goodsList + purpose
  promo.vue 选 promoTemplate=sale 与模块，配置各模块 config
      ↓ 存 activity（promoModules / goodsList / purpose / lat / lng ...）
C 端
  拉活动详情 → 按 promoModules 顺序渲染
      goods  读 goodsList
      purpose 读 purpose
      notice  读 description + config.html
      导航    点按钮 → uni.openLocation(lat, lng)
核销
  活动页领促销码 → channel-verification 生成码 → 门店 scan.vue 扫码核销
海报
  poster-template 取活动信息 + goodsList 前 N 件 → 生成海报 → 分享回流
看板
  activity-stats 聚合报名 / 核销；浏览由 zhao-track 上报
```

## 9. 错误处理与边界

- `goodsList` 为空或非法：`goods` 模块不渲染，不输出空壳。
- 单件商品缺 `promoPrice`：只显示原价；缺 `originPrice`：只显示促销价；两者皆缺：跳过该商品。
- `lat` / `lng` 缺失或为 0：导航按钮置灰并提示「场地暂未设置坐标」。
- `promoModules` 含未知 `type`：沿用现有 `normalizePromoModules` 过滤逻辑忽略。
- 手填价与到店价不一致：C 端固定展示「价格以到店为准」免责文案。
- 促销码重复领取：以 `channel-verification` 现有幂等规则为准，不额外新增逻辑。

## 10. 测试策略

- 单测（`web/tests`）：`normalizePromoModules` / `normalizeModuleConfig` 对 `goods` / `purpose` / `notice` 的归一化与非法输入过滤。
- 单测：`goodsList` 渲染边界（缺价、空列表）。
- 组件测试：`promo-goods` / `promo-purpose` / `promo-notice` 渲染结果。
- 接口测试：`activity` 含 `goodsList` / `purpose` 的创建与更新读写。
- 一致性测试：锁定 `PROMO_MODULE_TYPES` 与 C 端组件注册表一一对应，防止三处漂移。
- 手测：管理端配置 → C 端预览全链路；导航按钮点击；扫码核销；海报生成。

## 11. 风险与开放问题

1. **手填价格免责**：已在 C 端固定免责文案处理。
2. **三处同步契约漂移**：用一致性单测锁定，降低漏改风险。
3. **转化漏斗埋点**：需确认 `zhao-track` 是否已覆盖活动宣传页；未覆盖时本期先落地「报名 / 核销」两段漏斗，浏览埋点另立任务。
4. **优惠券升级为线上抵扣**：若后续提出，需另立 spec，牵涉 `zhao-deal` 交易链路，不在本期范围。
