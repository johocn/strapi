# 活动宣传 AI 制作（两页拆分）设计文档

> 日期：2026-08-25
> 状态：待审阅
> 关联：`docs/activity-ai-import-contract.md`（AI 导入契约，本设计补充配色与两页流程）

## 1. 背景与目标

现有"AI 生成活动数据 → 一键导入"已跑通脚本级验证（`scripts/import-ai-activity.cjs` + `test-import-contract.cjs`），但存在三个问题：

1. **客户决定的字段与 AI 生成混在一起**：分类/讲师/场地/系列/起止时间/权益/资料等客户拍板的信息，目前靠 AI 在 JSON 里生成，存在编造风险，且运营需事后手动改。
2. **宣传文案与固定信息耦合**：改动固定信息会影响文案，改动文案也要进同一张表单，难以独立反复调整。
3. **配色方案偏少且不可自定义**：仅 5 套模板绑定配色，无法覆盖各场景。

**目标**：将活动创建拆为「固定内容」「宣传文案」两页；固定内容预录入（含权益/资料/组图/表单/联系/配色），AI 仅基于固定内容生成针对性宣传文案；配色方案扩充至 12 套并支持按活动覆盖。

## 2. 用户流程（两页拆分）

```
后台活动列表
  ├── 新建活动 ──→ Step 1 固定内容页 ──保存──→ 草稿骨架(draft)
  │                                                  │
  │                                                  ▼
  │                                    Step 2 宣传文案页（独立）
  │                                    · AI 生成 / 手动编辑 / 粘贴导入
  │                                    · 可反复调整，不影响 Step 1
  └── 每行「宣传文案设计」链接 ──直达──→ Step 2（对已建活动）
```

- **Step 1 固定内容页**：活动编辑主体，预录入全部客户决定字段，保存即建草稿骨架。
- **Step 2 宣传文案页**：独立页面。入口 = 创建流程保存后引导跳转 + 活动列表「宣传文案设计」链接直达。可反复生成/调整，不动 Step 1 数据。

## 3. Step 1 预录入清单（客户决定，AI 不得编造）

| 区块 | 字段 | 现状 |
|---|---|---|
| 基本信息 | 标题、分类、讲师/场地/系列（下拉关联）、起止时间、名额、费用 | 已有 |
| 收费与签到 | 收费方式 flat/tier/factor、收费时机、签到方式、积分成本 | 已有 |
| 宣传组图 | 多图上传媒体库 + 每张**场景备注**（如"封面主图-亲子互动"） | **新增**（区别于现有 form.assets 录播/物料） |
| 权益配置 | 积分 / 优惠券 / 试听课程 / 课时·大纲（rewardConfig 四类型）+ 发放方式/条件 | 已有（rewardConfig 编辑器） |
| 资料 | 学习资料包（文章/课程关联）+ 报名问卷（questionnaire） | 部分已有，需补问卷编辑 |
| 报名表单 | formConfig 收集字段（表单编辑器） | 已有 |
| 联系方式 | promoContact 真实电话/微信/备注（替换占位） | 已有（占位需预录） |
| 模板+配色 | 5 结构模板 + 12 套配色色卡（可微调） | 模板已有；**配色新增** |

## 4. Step 2 宣传文案页

- **AI 生成**：提示词 = Step 1 全部固定内容（含权益/资料/组图场景备注/模板/配色）→ 调 `POST /ai/chat` → 返回宣传 JSON。
- **AI 输出范围**：`title` 建议、`description`、`promoModules`（cover 文案/highlights/agenda 描述/权益强调/FAQ/海报文案）、`formConfig` 建议补充字段（可勾选采纳，不自动写入）、`promoContact` 建议。
- **客户调整**：AI 结果回填为可编辑模块列表，手动改不影响 Step 1。
- **兜底**：展示提示词可复制；JSON 粘贴框手动导入（复用契约校验）。
- **保存**：仅写宣传字段，不动 Step 1 固定数据。

## 5. 架构（约束：不违反 zhao-point 单向依赖）

```
web 前端：组装提示词 + 解析校验 JSON（TS 版契约，移植 importActivity 逻辑）
   ↓ AI 调用                         ↓ 数据导入
zhao-studio /ai/chat（现有通用接口）    zhao-point admin 接口（现有）
```

- **zhao-point 零新依赖**，不调用 zhao-studio，单向依赖规则保持干净。
- 提示词组装、JSON 解析/校验放 web 前端 TS util。
- AI 只生成宣传字段，不生成时间/讲师/场地等客户已定字段 → 消除 AI 幻觉。

## 7. 数据模型改动

| 位置 | 改动 |
|---|---|
| activity schema | 新增 `promoColors`(json)；`assets` 语义扩展为 `[{url, scene?, note?}]`（兼容旧 `[{url}]`） |
| web 端 | 新增 `promo-palettes.js`（12 套色值）；Step 1 加组图上传+场景备注、配色选择器；Step 2 新宣传文案页；活动列表加「宣传文案设计」链接 |
| C 端 promo.vue | 读 `promoColors` 内联 CSS 变量覆盖模板默认；assets 兼容（封面优先 cover.bgImage 否则 assets[0].url） |

## 8. 风险点与兜底

1. **AI JSON 输出不稳定** → 复用契约校验（`test-import-contract.cjs` 逻辑移植前端 TS）+ 保留提示词复制/JSON 粘贴兜底。
2. **权限**：`/ai/chat` 需 `zhao-studio.ai.manage` 权限，活动运营角色需确认已授权。
3. **assets 旧数据兼容**：存量 `[{url}]` 需兼容读取。
4. **跨端配色一致**：C 端只认 promoColors 色值，无方案 id 二次维护。

## 9. 非目标（YAGNI）

- 不做 AI 生成完整样式/布局（保持"模板+配色覆盖"）。
- 不做系统内 AI 模型管理（复用 zhao-studio 现有 `callAI`/`/ai/chat`）。
- 不做跨活动文案模板复用。
