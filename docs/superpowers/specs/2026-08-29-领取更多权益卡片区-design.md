# 详情页「领取更多权益」卡片区（方案 A）设计文档

> 日期：2026-08-29　适用范围：C 端活动详情页（shao H5 + 微信小程序）与 zhao-point 后端插件

## 背景与目标

用户报名成功后，联系方式、问卷、关注、权益奖励等被挤在底部引导弹层里，发生遮挡，其他权益不可见、不可领。本设计在详情页信息模块下方新增常驻「领取更多权益」卡片区，目标：

1. 已报名用户能**看到**该活动全部可/未领权益及状态。
2. 联系方式 / 问卷 / 关注三项目报名后**真正做到**补领积分与解锁权益。
3. 彻底摆脱底部弹层遮挡；领完即时刷新状态。

经后端能力核实：问卷补领已支持（`fillQuestionnaire`）；**联系方式补领、关注补领、报名后权益状态查询**后端缺失，需新增。

## 后端（zhao-point）——需重构建部署

### 1. 新增接口：补填联系方式
`PUT /zhao-point/v1/my/activity/signup/:signupId/contact`　body `{ formData }`

逻辑（新增 `fillContact` 服务方法）：
- 校验 signup 存在且 `user==userId`、`status∈active/waiting`。
- 用 `collectFormData(formConfig, formData)` 校验并写回 `signup.formData`。
- 记录补填前后 `contactFilled` 达成差；补填后重算 unlock（`recomputeUnlock`）返回新增权益 `newlyGranted`。
- 若联系方式本轮新达成，补发 `activity_signup_contact +20`（`earnPointsSafe`，幂等）。
- 返回 `{ ok, unlockInfo, newlyUnlocked: newlyGranted, newlyContact }`。

### 2. 新增接口：补领关注
`PUT /zhao-point/v1/my/activity/signup/:signupId/subscribe`

逻辑（新增 `claimSubscribe` 服务方法）：
- 校验 signup 归属；`hasSubscribe(userId)` 若未关注返回 `{ subscribed:false }`。
- 已关注则补发 `follow_official_account +50`（`isOneTime` 幂等，已领自动跳过）。
- 重算 unlock 返回新增权益。
- 返回 `{ ok, subscribed, newlyUnlocked }`。

### 3. 新增接口：报名后权益状态
`GET /zhao-point/v1/my/activity/:signupId/unlock-status`

逻辑（新增 `signupUnlockStatus`）：
- 读 signup（含 activity、已填 formData/questionnaireData）。
- 返回 `{ formData, questionnaireData, contactDone, surveyDone, loginAuth, subscribed, rewards:[{id,name,type,mode,condition,unlocked}], pointsLeft }`。
- 数据用于已报名用户回访时卡片区渲染真实三态。

### 控制器 / 路由
- 控制器新增 `contact`、`subscribe`、`signupUnlockStatus` 三个方法，注册 `/my/activity/signup/:signupId/contact`、`/subscribe`、以及 `/my/activity/:signupId/unlock-status` 路由（登录态，复用现有鉴权）。

## 前端（shao/detail.vue）——H5 + 小程序同步

- `services/api.ts` 新增 `fillActivityContact(signupId, formData)`、`claimActivitySubscribe(signupId)`、`getSignupUnlockStatus(signupId)`。
- 详情页信息模块**下方**新增常驻卡片区，`v-if="signedUp && signupId"`，标题「领取更多权益 (+N 待解锁)」。
- 卡片项来源：`signupUnlockStatus`，三态渲染：
  - 已完成 → 绿色 ✓已领
  - 可领取 → 橙色「可领」高亮
  - 未达成 → 灰色锁（如关注未关注）
- 点击卡片内联弹对应表单（复用现有样式，非底部遮挡层）：
  - 联系方式 → 联系人表单（formConfig phone 字段）→ `fillActivityContact`
  - 问卷 → 现有问卷弹层 → `fillQuestionnaire`
  - 关注 → 公众号二维码 + 「我已关注，刷新」→ `claimActivitySubscribe`
  - 权益奖励 → 补领成功后自动解锁发放，卡片刷新为已领
- 每领完一项 → 重新 `getSignupUnlockStatus(signupId)` 刷新卡片与顶部「+N」。

## 数据流与幂等

- 所有补领以 `signupId` 为锚，校验 `user==本人 && status∈active/waiting`。
- `earnPointsSafe` 分项 try/catch + `isOneTime` 防重，单点失败不阻断。
- 关注未达成不领不扣分，返回明确提示。

## 范围外（不做）

- 不新增页面路由（方案 A 为内联，不复用方案 B）。
- 不改后端权益/积分规则定义。
- 关注防重复用既有 `follow_official_account isOneTime` 机制。

## 验证

1. 报名后回访：卡片区展示真实三态，数据来自 unlock-status。
2. 分别补填联系方式 / 问卷 / 关注，积分 +20 / +50 / +50 到账，卡片转已领，顶部 N 减少。
3. 幂等：重复提交同一补领积分不重复发放。
4. H5（v.joho.cn）与微信小程序（需重建上传）同步。
