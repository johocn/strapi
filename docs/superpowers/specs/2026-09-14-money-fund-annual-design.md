# 货币型产品多期限年化收益方案 设计文档

**日期**：2026-09-14
**状态**：待用户审阅
**范围**：仅处理产品3（幸福99，JQB2673J），不涉及通用货币型识别、监察页展示口径

---

## 1. 背景与问题

幸福99（产品3）为货币型（现金管理类）产品，杭银官网发布的净值恒为 `1.0`（行业惯例），真实收益体现在**万份收益**与**七日年化**。当前问题：

- 产品3 `productType = bank-wealth`（错误标注），年化快照按净值型复利口径计算，恒 1 净值导致所有期限年化 ≈ 0，对客户无评估价值
- 货币型计算分支（`nav-calculator.ts` 的 `calculateMoneyFundSnapshot`）仅支持 7日/1月/3月/6月/1年，缺少客户评估所需的 1日/3日/2周 期限
- C 端未提示"净值恒 1"的原因，客户易误判产品不涨

**设计初衷**：将单一产品的收益数据转换为 1日/3日/7日/2周/1月等期限的年化收益率，让客户评估理财产品好坏。

## 2. 目标

1. 产品3 按货币型口径计算多期限年化（1日/3日/7日/2周/1月/3月/6月/1年）
2. 双口径并标注：净值型复利、货币型万份收益单利；统一期限划分与 365 自然日基准；界面明确标注类型口径
3. 合规：不承诺保本保收益、标注"历史业绩不代表未来表现"、披露计算口径与依据、货币型展示监管允许的七日年化与万份收益、数据来源标注
4. C 端提示净值恒 1 的原因（产品卡片标识 + 计算说明弹窗 + 净值区文案）

## 3. 现状盘点

- **表结构完备**：`wealth_annual_snapshots` 已有 8 期限字段 `annual1d/3d/7d/2w/1m/3m/6m/1y`（decimal 10,6），`isEstimate` 标记
- **计算逻辑已有**（`nav-calculator.ts`）：
  - `calculateNavSnapshot`（净值型）：8 期限复利年化 `(期末/期初)^(365/自然日)-1`
  - `calculateMoneyFundSnapshot`（货币型）：仅 7日/1月/3月/6月/1年，单利 `窗口万份收益均值×365/10000`；`annual1d/3d/2w` 固定 null
- **分支依据**：`product.productType === 'money-fund'`
- **收益数据**：`wealth_money_incomes` 产品3 共 17 条（2026-08-27 ~ 09-13，数据源仅提供这些）
- **C 端**（`strapi-wealth/pages/detail/index.vue`）：已有年化趋势图（按期限切换）、期间年化、净值走势、净值表、净值来源链接、年化计算说明弹窗（已注明"货币基金按万份收益单利折算年化，与净值复利口径不同"）

## 4. 方案

### 4.1 数据修正

生产库执行：产品3 `productType: bank-wealth → money-fund`（一条 SQL）。此后 `calculateSnapshot` 自动走货币型分支。

### 4.2 货币型多期限补齐（后端 `nav-calculator.ts`）

`calculateMoneyFundSnapshot` 期限扩展为 8 期限，与净值型对齐：

| 期限 | 窗口（自然日） | 公式 |
|---|---|---|
| annual1d | 1 | 当日万份收益 × 365 / 10000 |
| annual3d | 3 | 近3天万份收益均值 × 365 / 10000 |
| annual7d | 7 | 近7天万份收益均值 × 365 / 10000 |
| annual2w | 14 | 近14天万份收益均值 × 365 / 10000 |
| annual1m | 30 | 近30天万份收益均值 × 365 / 10000 |
| annual3m | 90 | 近90天万份收益均值 × 365 / 10000 |
| annual6m | 180 | 近180天万份收益均值 × 365 / 10000 |
| annual1y | 365 | 近365天万份收益均值 × 365 / 10000 |

规则：
- 统一单利口径（与货基监管披露口径一致）：`calculateMoneyFundAnnual(窗口万份收益总和, 窗口天数)`
- 窗口内收益数据不足窗口天数 → 该期限为 `null`（前端显示"待积累"），不输出假数据；现有实现按"记录数 < 窗口天数"判定
- 缺失日期收益按 0 计入均值（现有实现已如此，货基惯例）
- `isEstimate` 沿用货币型现有逻辑（false），不引入估算标记扩展（YAGNI）

### 4.3 重算与验证

部署后触发产品3 年化快照重算（复用 `recalculateSnapshots` 或 `recalculateMissing` 补缺接口）。预期：1日/3日/7日/2周 有值，1月及以上为 null（待积累）。

### 4.4 合规（通用监管清单，落地 C 端）

1. 年化区固定文案：**"历史业绩不代表未来表现"**
2. 计算说明弹窗补充：**"货币型产品净值恒为 1，收益以万份收益/七日年化体现，按单利折算年化，与净值型复利口径不同"**
3. 数据来源链接（`navSourceUrl`）保留；不承诺保本保收益（全站无预期收益类文案）

### 4.5 C 端提示净值恒 1（`strapi-wealth/pages/detail/index.vue`，仅对 `money-fund` 生效）

1. **产品卡片**：加"现金管理类"标识
2. **年化计算说明弹窗**：补充净值恒 1 原因（同 4.4-2）
3. **净值走势图/净值表区**：提示"本产品为现金管理类，净值恒为 1，收益体现于万份收益/七日年化"

## 5. 测试

1. 货币型 1日：当日万份收益 → 年化 = 万份收益×365/10000

3. 窗口数据不足 → null（待积累）
