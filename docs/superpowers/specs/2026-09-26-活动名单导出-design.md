# 活动报名/到场名单导出设计（zhao-point × web）

> 日期：2026-09-26
> 范围约束：**只做「把活动报名名单连同到场状态导出成文件」这一件事**。不改报名/签到/候补业务规则、不新增权限点、不改数据模型、不引入新依赖、不做爽约落库标记。
> 上线批次：**basic（后端）先上，web（管理端）后上**——前端按钮指向新接口，顺序颠倒会出现 404 空窗。

## 1. 问题与证据

线下活动结束后的标准动作是「拿名单去现场点名 / 事后核对爽约」。当前管理端只能**在页面上逐条看**，没有任何导出通道：

- 报名名单页 [signups.vue](file:///e:/code/web/src/pages/activity/signups.vue) 两个 tab（报名名单 / 到场记录）都是纯展示，无导出按钮。
- 后端仅有 `GET /adm/activities/:documentId/signups`（[controllers/activity.ts:657-671](file:///e:/code/basic/plugins/zhao-point/server/src/controllers/activity.ts#L657-L671)）与 `.../attendance`（[:766-781](file:///e:/code/basic/plugins/zhao-point/server/src/controllers/activity.ts#L766-L781)）两个 JSON 列表接口，返回的名单**不含到场状态**（要到另一个接口、自己比对），也没有任何 `text/csv` 出口（全仓 grep 无 `text/csv` 命中）。
- 运营现状：要么手工抄，要么在浏览器里对着两个 tab 交叉比对——活动 100 人时基本不可用。

**结论**：缺口是「**名单 + 到场状态的单文件视图**」，不是权限或数据缺失——数据都在（`activity_signups.formData` 存报名表单、`activity_attendances` 存到场记录），只是没有被组装导出。

## 2. 目标与非目标

**目标**

1. 管理端在活动报名名单页一键导出**全量名单 CSV**，一行一人，同时给出**已到场 / 未到场 / 已取消**状态。
2. 导出内容包含报名表单自定义字段（姓名、手机号等），列名取活动 `formConfig` 的 `label`，顺序与配置一致。
3. 明文导出（沿用现有报名名单的可见范围），仅限有 `activity.read` 权限且通过渠道/租户校验的管理端账号。
4. 「未到场」= **有 active 报名但无到场记录**，由到场记录推导，**不新增字段、不改数据模型**。

**非目标**

- 不做爽约（no-show）落库标记、不做爽约 SOP 统计改造（另立需求）。
- 不做 XLSX（避免引入 `xlsx` 依赖；CSV 加 UTF-8 BOM 即可被 Excel 正确打开）。
- 不做导出字段勾选、不做分页/异步导出任务、不做导出审计日志。
- 不改 `adminSignups` / `adminAttendance` 既有 JSON 接口的返回结构（避免影响现有页面）。

## 3. 导出内容

### 3.1 列定义

固定列 **9 列**，后接**动态列**（活动 `formConfig` 每个字段一列）：

| # | 列名 | 取值 | 缺省 |
|---|---|---|---|
| 1 | 序号 | 1..n，按 `signupAt` **升序**（报名先后） | — |
| 2 | 用户ID | `signup.user.id` | 空 |
| 3 | 昵称 | `user.nickname` → `user.username` → `用户#{id}` | — |
| 4 | 报名状态 | `active→已报名` / `waiting→候补中` / `cancelled→已取消`（未知值原样输出） | — |
| 5 | 到场状态 | 见 3.2 | — |
| 6 | 核销方式 | `self→自助核销` / `worker_scan→工作人员扫码` / `manual→手动核销` | 空（无到场记录） |
| 7 | 报名时间 | `signupAt`，固定格式化 | 空 |
| 8 | 到场时间 | `attendance.checkinAt`，固定格式化 | 空 |
| 9 | 扣除积分 | `pointsCharged`（无值按 0） | 0 |
| 10+ | `formConfig[i].label` | `formData[key]`，`multi` 数组用 `、` 连接 | 空 |

### 3.2 到场状态推导（本特性的核心规则）

优先级从高到低，**取消优先于到场**（已取消的报名不该再算到场）：

| 条件 | 到场状态 |
|---|---|
| `signup.status === "cancelled"` | `已取消` |
| 有该 `signup` 的到场记录（`activity_attendances.signup`） | `已到场` |
| 其余（`active` / `waiting` 且无到场记录） | `未到场` |

即：**未到场 = 报名仍在册（含候补）但从未核销到场**，正是运营口径的爽约集合。候补未转正且未到场同样计入「未到场」，一眼可辨（配合第 4 列「候补中」区分）。

### 3.3 时间格式

固定输出 `YYYY-MM-DD HH:mm`，**强制按 UTC+8 换算**（不依赖服务器时区，避免线上 UTC 导致整列偏 8 小时）。非法/空值输出空字符串。

## 4. 接口设计

```
GET /api/zhao-point/v1/admin/adm/activities/:documentId/signups/export
```

- 路由使用**既有的 `channelScopeRoute`**（`is-authenticated` → `has-permission(activity.read)` → `has-channel-scope` → `has-tenant-access`），权限点复用 `activity.read`，**不新增权限点、不脱敏**（与页面可见范围一致）。
- 响应：

```
HTTP 200
Content-Type: text/csv; charset=utf-8
Content-Disposition: attachment; filename="signups.csv"; filename*=UTF-8''<活动标题_日期>
Content-Length: <n>
body = UTF-8 BOM + CSV 文本
```

- 错误：活动不存在 → `404 {error:"活动不存在"}`；无权限由策略层返回 `403`（沿用插件统一模式，HTTP 状态由策略给出）。

**为什么后端出 CSV 而不是前端拼**：

1. 数据组装（表单字段 × 到场记录 join）在后端一次完成，前端不必拉两个列表再对齐；
2. 复用 `channelScopeRoute` 的完整鉴权链，前端只触发下载，无绕过面；
3. 与既有下载接口（`zhao-quiz` 的 `quiz-batches/template/download`）模式一致，前端 `downloadFile()` 工具已存在。

## 5. CSV 规格

| 项 | 规定 | 理由 |
|---|---|---|
| 编码 | UTF-8 **带 BOM**（`\uFEFF` 开头） | 否则 Excel 打开中文列名乱码 |
| 行尾 | `CRLF`（`\r\n`） | Excel/Windows 兼容 |
| 转义 | **所有单元格统一双引号包裹**，内部 `"` 翻倍为 `""` | 报名表单内容常含逗号/换行，全量引用最稳 |
| 表头 | 第一行 | — |
| 数组值 | `、` 连接 | `multi` 型表单字段 |
| 公式注入 | **不处理**（不加前置单引号） | 明文导出、仅限管理端内部使用；此取舍在设计中显式记录 |

> 公式注入取舍说明：`=SUM(...)` 之类文本在 Excel 中会被当公式。本导出仅供内部运营（2 人以下），且加了转义规则后风险面极小；如后续对外分发再补 `'` 前缀规则。

## 7. 验收标准

1. 未登录访问导出接口 → `401/403`（**不是 404**，证明路由已注册且 dist 已重建）。
2. 有 `activity.read` 且有渠道权限的账号导出 → `200`，`Content-Type: text/csv; charset=utf-8`，body 首字节为 `EF BB BF`（BOM）。
3. 列出某活动全部报名，含 `未到场` 与 `已到场` 两种状态；已取消报名的到场状态为 `已取消`。
4. 报名表单自定义字段（姓名/手机号）出现在动态列，表头为配置的 `label`，含逗号/引号的取值不破坏列结构（Excel 打开列数正确）。
5. 管理页点击「导出名单（CSV）」→ 浏览器保存文件，Excel 打开中文不乱码。
6. 无任何活动报名的空活动导出 → 仅表头行，`200`。

## 8. 风险与取舍

| 风险 | 处置 |
|---|---|
| 到场记录 join 用关系字段，可能踩 `{id:N}` 形状坑（本轮已两次线上事故） | 统一走 `relId()` 归一，并对 `NaN` 兜底跳过；单测**必须用 `{id:N}` 对象形态**入参 |
| 大数据量活动（数百人）同步生成 | 一次性全量拉取内存生成，量级可控（活动容量默认 100）；不做流式 |
| 导出接口被越权调用 | 复用 `channelScopeRoute` 四道门（含渠道/租户），与页面可见范围一致 |
| 文件名中文在部分浏览器失真 | 前端由 `downloadFile` 的 `filename` 主导保存名，后端 `Content-Disposition` 仅作补充 |
| 全量 attendance 拉取（`adminAttendance` 同款写法） | 沿用既有可用写法，避免引入未验证的关系过滤语法 |
