# 文章发布统一入口 + 公共基础组件 设计文档

- 日期：2026-09-12
- 仓库：`e:\code\web`（H5 管理端，GEO/资讯文章发布页所在）
- 关联后端插件：`zhao-website`（`e:\code\basic\plugins\zhao-website`）
- 状态：待评审

## 1. 背景与现状

`zhao-website` 插件承载两类**内容类型（content-type）**，前端在 `e:\code\web` 各有一套独立页面：

| 内容类型 | 表 | 前端页面 | 定位 |
|---|---|---|---|
| 普通资讯文章 | `zhao_website_articles` | `pages/website/article/{list,edit}.vue` | 品牌资讯/新闻/深度长文 |
| GEO 增长页 | `zhao_website_geo_articles` | `pages/website/geo-article/{list,edit}.vue` | 本地 SEO 增长 + 转化页 |

**生产数据实测（joho，2026-09-12，只读）：**

```
 zhao_website_articles     |     0
 zhao_website_geo_articles |     4   （全部 status=published）
```

关键事实：
- **普通文章表当前为空（0 行）**，站内真实内容全部在 geo-article。
- 两组菜单共用同一权限位 `menu.website-article`（`dashboard/index.vue` L150-157）。
- 两类 schema 均提供完整 CT 接口（`/articles` 与 `/geo-articles`，`zhao-website/routes/content-api.ts`）。

## 2. 必要性分析：二者是否应该共存

### 结论：schema 层保留两类是正确的，但前端入口需收敛

两类的**语义、生命周期、合规约束不重叠**，是互补而非替代关系：

- **普通资讯文章**：内容品牌资产 + 站内泛资讯。特征字段 = OG/sitemap/统计量（isFeatured / isPinned / viewCount / likeCount）、readingTime、`sourceArticleDraft`（关联 zhao-studio 稿件）、brandVoice、mainEntity。角色是"品牌内容仓"，重原创与声量，轻地域。
- **GEO 增长页**：本地抢占流量。地域词标题、真值背书、知识实体、E-E-A-T 证据链、风险合规（riskType/reviewChecks/审核人）、转化（CTA/留资/积分/小程序）、五种子类型（geo-faq / local-report / local-comparison / local-list）。状态机含 `review` 态 + 发布门禁 + audit-check。

**合并成一个 content-type 不可行**：字段差 60+，要么让轻量资讯被重型 GEO 门禁拖垮，要么让 GEO 校验被空态污染；且 `zhao_website_articles` 无 site 关系存储（历史遗留，site 过滤实际不生效），迁移风险高、无收益。

**因此：后端/数据模型保持分离；只在前端"发布入口/心智引导"层收敛。**

### 决策（已确认）
**保留双入口 + 类型引导**：不做数据迁移、不删除普通资讯入口，通过一个统一发布入口让运营者先选类型、附带约束说明，防止选错。

## 3. 方案 A：统一发布入口

### 3.1 目标
- 解决"运营者不知该建普通资讯还是 GEO、及其 5 种子类型"的心智问题。
- 收敛 dashboard 上两个平级卡片为一个"发布文章"入口。

### 3.2 交互流程

```
dashboard「发布文章」卡片
        ↓
  类型选择页 type-selector
   ├─ 本地 GEO 增长页（默认置顶、已用中）
   │     ├─ GEO 文章 / GEO 问答 / 本地报告 / 本地对比 / 本地清单
   │     └─ → geo-article/edit.vue（type 预设）
   └─ 品牌资讯文章（标"当前未使用"弱提示）
         └─ → article/edit.vue
```

- 类型选择页每项附一行**适用场景 + 关键约束**：
  - GEO：需真值背书、知识实体、E-E-A-T 证据链、合规验收；本地地域词标题。
  - 品牌资讯：原创/品牌栏目，无发布门禁。
- GEO 条目默认高亮并置顶（生产唯一在用内容）。

### 3.3 实现点（前端，`web/src/pages/website`）
1. 新增页面 `type-selector.vue`（选择卡片 + 说明文案 + 带 type 参数 `navigateTo`）。
2. 注册路由：`pages.json` 增加 `pages/website/type-selector`。
3. `geo-article/edit.vue` 的 `onLoad` 支持 `options.type` 预设 `form.type`（已有 type 联动逻辑，微调即可）。
4. `dashboard/index.vue`：将「资讯文章」与「GEO 文章」两张卡片收敛为一张「发布文章」→ type-selector；**保持 `menu.website-article` 权限位，不加新权限**。
5. 兼容：旧直达路由（`/pages/website/article/list` 等）保持不变。

### 3.4 不做的事（YAGNI）
- 不做数据迁移、不删表、不改后端 content-type。
- 不引入新依赖、不改 vue 版本（遵守 web/shao 目录铁律）。

## 4. 方案 B：公用基础组件 `ArticleBaseForm`

### 4.1 动机
两种表单重复了(title / slug / category(关系) / tags / 正文 content / metaTitle / metaDescription / canonicalUrl / allowIndex / noFollow)等字段的模板与逻辑。

### 4.2 组件契约
新建 `web/src/components/ArticleBaseForm.vue`：

- **props**
  - `modelValue: object`（v-model 双向绑定，承载公共字段）
  - `siteId: string`（标签/分类懒加载作用域）
  - `definitions?: { fields: string[] }`（可选：控制渲染哪些字段，默认全量）
- **emits**：`update:modelValue`
- **内部职责**：纯展示 + v-model 绑定；懒加载 `tag` / `article-category` 选项（复用 `api/tag.js` + `articleCategoryApi`）。
- **公共字段默认清单**：title、slug、category、tags、content、metaTitle、metaDescription、canonicalUrl、allowIndex、noFollow。

### 4.3 边界（防过度耦合）
- **只做展示与绑定，不含业务校验、类型联动、发布门禁、audit-check。**
- GEO 特有字段（真值绑定/知识实体/E-E-A-T/风险合规/核心三模块/CTA 等）及类型联动**仍留在 `geo-article/edit.vue`**，不进入公共组件。
- 如此避免把重型 GEO 逻辑混入、被普通资讯拖累。

### 4.4 接入
- `article/edit.vue`：以 `ArticleBaseForm` 替换"基本信息 + SEO 配置"两块。
- `geo-article/edit.vue`：以 `ArticleBaseForm` 替换"基本信息 + 结构化与 SEO"中重叠字段部分；GEO 专项保持 page 内。
- 两页各自保留独有的 PageHeader 按钮（存草稿/发布前检查/发布）与发布逻辑，不改后端 API。

## 6. 风险与注意

- cookie/缓存：改动后需 C 端硬刷新（Ctrl+F5）清缓存（沿用历史经验）。
- 权限：入口收敛不改权限位，`menu.website-article` 仍同时控制两类，避免权限漂移。
- 退出策略：类型引导是纯前端收敛，回滚即恢复 dashboard 原卡片 + 页面路由，无数据副作用。
