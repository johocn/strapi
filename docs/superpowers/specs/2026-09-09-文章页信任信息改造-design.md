# 文章页「权威依据/文中涉及」信任信息改造设计

日期：2026-09-09
状态：已确认

## 1. 背景与问题

当前 C 端文章页「权威依据」「文中涉及」板块是**机器校验元数据的原始导出**：

- 「权威依据」逐条罗列真值声明定义（含大量基础概念：教育是…、学习是…、课程是…），读者看不出它支撑正文哪句话，属于「为了标注而标注」；

- 「文中涉及」罗列全部知识实体（多为 DefinedTerm 通用概念），列表长、滚动成本高；

- 两块内容占阅读空间，对普通读者几乎无增益。

数据现状（生产库）：

- `first-truth-policy` 共 18 条：8 条品牌主张类（joho.cn 品牌主张…）+ 10 条通用定义类（other：教育/学习/课程/在线教育/终身学习…）；文章关联其中 10 条；

- `knowledge-entity` 共 16 个，绝大多数为 DefinedTerm（教育/学习/课程/在线教育/在线课程/学习方法/学习资源/职业教育/学历教育/考试认证/知识付费/终身学习），外加 Organization（joho.cn）、Place（中国）等；

- 真值声明无「对应正文段落」字段；实体无「强相关/弱相关」标记。

## 2. 改造目标

把「机器校验元数据」改造成「用户可读的信任信息」：

1. **权威依据**：一句话总述 + 可展开详情；只保留支撑本文核心论点的依据，过滤通用定义；每条依据标注对应正文段落；
2. **文中涉及**：标签化展示，只留强相关实体，过滤通用概念；
3. **AI 内容与用户内容分离**：用户看精简版；爬虫/LLM 通过 JSON-LD 看完整元数据（含未绑定、通用概念），SEO 不降级。

## 3. 设计决策（已与用户确认）

| 决策点     | 选择                                    |
| ------- | ------------------------------------- |
| 改造范围    | 前端 + 后端绑段（真值声明绑定正文段落）                 |
| 展示形态    | 方案1 精简版（总述 + 折叠详情 + 段落绑定标注）           |
| 通用概念过滤  | 前端黑名单（零后端改动）                          |
| AI/用户分离 | 折叠分层 + JSON-LD 完整数据（不新增 aiContent 字段） |
| 绑段数据形态  | 文章侧 JSON 字段 `truthBasisSections`      |

## 4. 后端改动（basic 仓库，zhao-website 插件）

### 4.1 schema：geo-article 新增字段

`plugins/zhao-website/server/src/content-types/geo-article/schema.json` 新增：

```json
"truthBasisSections": {
  "type": "json",
  "default": [],
  "description": "真值声明绑定正文段落：[{claimKey, section}]，section 为正文 H2 标题（如『二、长期学习规划四步法』）"
}
```

- `claimKey` 为 `first-truth-policy` 现有唯一键字段，用于匹配文章侧绑定 → 真值声明；

- JSON 字段随 content-api/admin-api 默认返回，**零接口改动**；

- 旧文章无此字段 → 空数组，前端兜底不报错。

## 5. 管理端改动（web 仓库，geo-article/edit.vue）

「真值声明」编辑区每条声明旁新增\*\*「绑定段落」\*\*下拉选择：

- 选项自动从当前文章正文 content 的 `<h2>` 标题提取（如「二、长期学习规划四步法」），另附「开篇」「结语」与自定义输入；

- 未绑定 = 该条不进用户视觉列表（仅 AI/JSON-LD 保留）；

- 提交时生成 `truthBasisSections: [{claimKey, section}]`；

- 编辑回显时按 claimKey 反查填充下拉。

## 6. C 端展示改动（strapi-site 仓库）

### 6.1 用户侧（视觉精简）

**权威依据**（`components/modules/geo/TruthBasis.tsx` 重构）：

- 默认可见一行**总述**：由 `sourceName` + 绑定数量动态生成，如「本文观点参考中华人民共和国教育部相关政策，配套 4 条核心依据」；

- `<details>` 展开后**只展示已绑定段落的依据**，每条标注「对应：二、长期学习规划四步法」；通用定义（claim 为「X 是…」且未绑定）不进入视觉列表；

- 若文章无绑定（旧数据），兜底展示前 N 条声明 + 「查看全部」。

**文中涉及**（`components/modules/geo/EntityMentions.tsx` 重构）：

- 改为标签云（chip 样式），前端黑名单过滤通用概念；

- 保留 `<details>` 折叠语义，展开显示标签；

- 无强相关实体时整块隐藏。

**信息边界/本地贴士**：文案上轮已优化为易懂版，展示组件保持。

### 6.2 AI 侧（结构化数据）

`lib/geo-seo.ts` 的 `buildGeoJsonLd` 为 Article 类型补充：

- `mentions`：完整 mentionedEntities（name/entityType/url）；

- `citation` / `isBasedOn`：完整 truthBasis（claim/canonicalSourceUrl/canonicalValue/verificationStatus）。

未绑定与通用概念也包含，实现「AI 看完整、用户看精简」。

### 6.3 前端黑名单

```ts
// 通用概念词（DefinedTerm 基础概念，用户不可见）
const GENERIC_ENTITY_WORDS = ["教育","学习","课程","在线教育","在线课程","学习方法","学习资源","学历教育","考试认证"];
```

过滤规则：`entityType === "DefinedTerm" && GENERIC_ENTITY_WORDS.includes(name)` → 过滤。

## 7. 风险与边界

- `truthBasisSections` 为纯新增 JSON 字段，不破坏现有文章与关系；

- 黑名单只影响视觉渲染，DOM/JSON-LD 数据完整，SEO 不降级；

- **部署铁律**：zhao-website 插件 `server/src` 改动后必须 `npm run build` 重建 dist 并 commit+push，再走 deploy.sh；否则新字段不随接口返回，前端读取不到、功能静默失效；

- 绑段下拉解析 `<h2>`：文章 content 由富文本生成，需兼容 `h2`/`h3` 与无标题开头段（映射为「开篇」）。

## 8. 验收标准

1. 线上文章页「权威依据」默认只显示一行总述，展开后仅含绑定段落依据且标注段落；
2. 「文中涉及」仅显示强相关实体标签（职业教育/终身学习/知识付费等），无「教育」「学习」等通用词；
3. 页面 HTML 含完整 truthBasis/mentionedEntities 数据，JSON-LD 含完整元数据（curl/grep 验证）；
4. 管理端文章编辑页可绑定段落，回显正确；
5. 旧文章（无绑定）页面正常渲染，无报错。
