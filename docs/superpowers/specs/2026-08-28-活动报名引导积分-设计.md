# 活动报名引导 + 分级积分 设计文档

> **日期：** 2026-08-28
> **范围：** shao（C端 H5）活动详情页报名引导、zhao-point（活动报名/积分）、zhao-third（微信授权）、zhao-sso（公众号二维码）、zhao-auth（用户资料）

## 一、目标

1. **报名引导不再依赖 rewardConfig**：微信环境点「报名」必走对比法引导；活动未配置权益时，以内置分级积分兜底，仍展示完整引导。
2. **分级积分**：按用户实际达成项累加发放（静默5 / 授权10 / 联系方式20 / 问卷50 / 关注50）。
3. **对比法引导**：微信环境第一步固定为「静默登录 vs 授权登录」对比——授权登录突出主推（积分 + 模板消息通知），静默登录弱化小字。
4. **引导关注公众号**：展示公众号二维码，关注后确认刷新，发放关注积分。
5. **授权登录补全资料**：授权回调后，用户缺头像/昵称时用微信信息补充。

## 二、现状诊断（根因）

| # | 问题 | 位置 |
|---|------|------|
| 1 | `onSignup` 仅当 `rewardCfg && isWechatBrowser()` 才走引导弹层，活动无 rewardConfig 时无任何引导 | shao/pages/activity/detail.vue |
| 2 | `resolveGuideStep` 仅在通道 `wechat_auth` 且未授权时才先出对比页；contact/survey/subscribe 通道不先做登录对比 | detail.vue |
| 3 | 后端 `signup` 固定发 `activity_signup`（默认5分），无分级积分 | zhao-point/services/activity.ts |
| 4 | 前端无「关注公众号」引导 UI；二维码仅 admin 路由，无 C 端接口 | zhao-sso/routes/admin.ts |
| 5 | 授权回调创建用户时不写头像昵称到 up_users | zhao-third/services/third-party-auth.ts |

## 三、方案选型

**采用方案 A：内置积分兜底 + 对比法引导**（已获用户确认）

- 引导与 rewardConfig 解耦：微信环境无条件进引导。
- 分级积分对所有活动生效（无权益也有积分兜底）。
- rewardConfig 自定义权益（优惠券/试听课等）作为额外奖励叠加，逻辑不变。
- 对比法视觉：授权登录大卡突出（渐变高亮、列出 积分10+模板通知）；静默登录小字弱化（次级样式、兜底入口）。

## 四、架构

```
┌─ shao（前端）────────────────────────────────────────────┐
│ detail.vue 报名引导（4步线性向导，微信环境必走）             │
│  Step1 login 对比法 → Step2 info(条件) → Step3 follow(条件) │
│  → Step4 reward(条件) → confirm                             │
│  调用 unlockCheck 获取 pointsPreview 展示积分明细            │
│  调用 GET /zhao-sso/v1/wx/qrcode 获取公众号二维码            │
└────────────────────────────────────────────────────────────┘
              │ unlockCheck / signup（携带 formData/questionnaire）
              ▼
┌─ zhao-point（后端）────────────────────────────────────────┐
│ unlockCheck：返回 loginAuth/subscribed/pointsPreview（无     │
│   rewardConfig 也返回）                                      │
│ signup：按达成项累加发放分级积分（新增 3 个 action + 复用     │
│   follow_official_account）                                  │
└────────────────────────────────────────────────────────────┘
              │ 授权回调（snsapi_userinfo）
              ▼
┌─ zhao-third / zhao-auth ───────────────────────────────────┐
│ handleCallback：创建/绑定用户后，用微信信息补全头像昵称        │
└────────────────────────────────────────────────────────────┘
              │ 关注二维码
              ▼
┌─ zhao-sso ─────────────────────────────────────────────────┐
│ 新增 C 端路由：GET /v1/wx/qrcode 复用 sso-wx-qrcode 返回 wx_url │
└────────────────────────────────────────────────────────────┘
```

**模块职责与依赖：**
- 前端 detail.vue：引导流程编排、对比法 UI、积分明细展示、关注二维码展示与确认刷新。
- zhao-point activity.ts：积分计算单一来源（`computePointsPreview` 与发放共用），unlockCheck 与 signup 均调用。
- zhao-third third-party-auth.ts：授权回调后补全用户资料。
- zhao-sso：C 端公众号二维码接口（复用现有 sso-wx-qrcode）。
- zhao-auth：提供 `updateProfile(userId, { nickname, avatar })` 供第三方回调补全资料。

## 五、详细设计

### 5.1 分级积分规则（后端唯一来源）

| 达成项 | 积分 | action | 判定 | 备注 |
|--------|------|--------|------|------|
| 基础报名 | +5 | `activity_signup`（已有） | 报名成功 | 保留现有调用 |
| 微信授权登录 | +5（累计10） | `activity_signup_auth`（新增） | `hasWechatAuth` | |
| 填姓名+联系方式 | +20 | `activity_signup_contact`（新增） | `contactFilled(formConfig, formData)` | |
| 回答问卷 | +50 | `activity_signup_survey`（新增） | `surveyFilled(questionnaireData)` | |
| 关注公众号 | +50 | `follow_official_account`（改默认 10→50） | `hasSubscribe` 且未领过（isOneTime） | 报名时补发 |

- 全累加：授权10 + 联系方式20 + 问卷50 + 关注50 = 最高 130 分/场。
- 新增 3 个 action 配置（`zhao-point/server/src/config/index.ts` increaseRules）：
  `activity_signup_auth / activity_signup_contact / activity_signup_survey`，均 `points` 默认按上表、`isOneTime: false`、`limitPerDay: 0`、`taskGroup: "activity"`、`description` 中文。
- `follow_official_account` 默认 points 10 → 50（isOneTime 不变）。

### 5.2 后端 zhao-point/services/activity.ts

**新增 `computePointsPreview({ loginAuth, subscribed, conditions })`：**
返回 `{ base: 5, auth: 5, contact: 20, survey: 50, subscribe: 50, total }`（按达成项置零后求 total）。

**新增 `grantActivityPoints(strapi, userId, { loginAuth, subscribed, conditions })`：**
- 保留 `grantPoints(strapi, userId, "activity_signup", "活动报名")`（基础5）。
- `loginAuth` → `earnPoints({ action: "activity_signup_auth", points: 5, source: "activity", method: "activity_signup", remark: "微信授权登录报名" })`。
- `conditions.contact` → `earnPoints({ action: "activity_signup_contact", points: 20, ... remark: "完善联系方式报名" })`。
- `conditions.survey` → `earnPoints({ action: "activity_signup_survey", points: 50, ... remark: "回答问卷报名" })`。
- `subscribed` → 补发关注奖励（一次性防重由 `follow_official_account` isOneTime 保证）：`earnPoints({ action: "follow_official_account", ... })`（不传 points 用规则默认 50）。
- 各 earnPoints 需传 `userChannelId`（`resolveUserChannelId`，与现有 grantReward 一致）。
- 幂等：报名唯一（现有 dup 检查）；关注奖励 isOneTime 防重。

**signup 改造：**
- rewardConfig 存在时维持现有 reward 判定逻辑不变。
- 报名成功后（active 分支）在 `grantPoints` 处改为调用 `grantActivityPoints`（内部含基础分 + 各达成项），`loginAuth/subscribed/conditions` 在报名时已计算（现仅 hasReward 分支内计算，需**提前到 hasReward 之外**计算，供无 rewardConfig 时使用）。
- 返回值 `unlockInfo` 增加 `pointsPreview`（供前端报名后展示/校验）。

**unlockCheck 改造：**
- 无 rewardConfig 时不再直接返回 `{ ok, hasReward:false }`，改为返回：
  `{ ok: true, hasReward: false, loginAuth, subscribed, conditions, pointsPreview }`。
- 有 rewardConfig 时在现有返回基础上追加 `pointsPreview`。

### 5.3 前端 shao/pages/activity/detail.vue

**onSignup 触发改造：**
```
if (isWechatBrowser()) → openRewardGuide()   // 微信环境无条件引导（不再依赖 rewardCfg）
else if (formFields.length) → openSignupForm()
else → doSignup()
```

**引导步进改为线性向导：**
`resolveGuideStep()` 改为按序计算下一步：
1. `login`：未授权（`!loginAuth`）必出对比法；已授权跳过。
2. `info`：有 formFields 或 questionnaireFields 且信息未填 → 展示完善信息（积分提示：联系方式+20、问卷+50）；无则跳过。
3. `follow`：未关注（`!subscribed`）且二维码可用 → 展示关注引导（积分+50）；已关注跳过。
4. `reward`：有 rewardConfig 解锁权益才展示；否则直接到 confirm。
5. `confirm`：汇总积分明细（pointsPreview）+ 已解锁权益，确认报名。

**对比法 Step1（login）视觉：**
- 授权登录：主卡片，渐变高亮背景，权益列表（积分 +5（累计10）· 模板消息通知报名进度/候补转正）；按钮「微信授权登录」主样式。
- 静默登录：小字弱化，次级链接样式置于下方；文案「直接报名（基础5积分）」。
- 已授权登录用户直接跳过本步。

**关注引导 Step3（follow）：**
- 调 `GET /zhao-sso/v1/wx/qrcode?scene=act_follow:{activityId}` 获取 `wx_url`，展示二维码图片（长按识别关注）。
- 按钮「我已关注，刷新」→ 调 `refreshSubscribeStatus()`（现有逻辑）→ 已关注则 `subscribed=true` 发放关注积分并推进下一步；未关注 toast 提示重试。
- 二维码接口失败/未配置公众号 → 跳过本步（不阻塞报名）。

**授权回调恢复：** 保留 `REWARD_GUIDE_KEY` 机制（`chooseAuthLogin` 写入，回调恢复 `loginAuth` 后从 info 继续）。

**积分明细展示：** Step1/Step2/Step3/confirm 的积分数字来自 `unlockCheck` 返回的 `pointsPreview`（单一来源，避免前端硬编码漂移）；接口异常时降级为固定文案值。

### 5.4 公众号二维码 C 端接口（zhao-sso）

- **新增** `zhao-sso/server/src/routes` 公开路由：`GET /zhao-sso/v1/wx/qrcode?scene=xxx`。
- controller 复用 `sso-wx-qrcode` service：按 `scene_key` 查现有带参二维码，无则创建（`scene_key` = `act_follow:{activityId}`），返回 `{ wx_url }`（`https://mp.weixin.qq.com/cgi-bin/showqrcode?ticket=...`）。
- 未配置公众号凭据时返回 `{ wx_url: null }`，前端跳过关注步。

### 5.5 授权登录补全资料（zhao-third + zhao-auth）

- zhao-auth 新增 service `updateProfile(userId, { nickname, avatar })`：仅当目标字段为空时写入 up_users。
- third-party-auth.ts `handleCallback`：
  - 创建新用户或绑定已有用户成功后，若微信 userinfo 含 nickname/headimgurl：
    - 调 `updateProfile(userId, { nickname, avatar })` 补充缺失字段。
  - `hasSubscribe` 已有实现，无需改动。

## 六、数据流

```
1. 用户点「报名」→ onSignup（微信环境）→ openRewardGuide
2. openRewardGuide → unlockCheck → { loginAuth, subscribed, pointsPreview }
3. 未授权 → Step1 对比法：
   - 授权登录 → redirectToWechatAuth('snsapi_userinfo') → 微信回调
     → third-party-auth handleCallback（补全头像昵称）→ auth-callback 页写登录态
     → 回详情页恢复引导（REWARD_GUIDE_KEY, loginAuth=true）
   - 静默登录 → 跳过（loginAuth=false）
4. Step2 info：填姓名联系方式（+20）、问卷（+50）
5. Step3 follow：展示二维码 → 关注 → 点「我已关注，刷新」→ unlockCheck 刷新 subscribed
6. Step4 reward / confirm：展示 pointsPreview 积分明细 → confirmGuideSignup
7. signup（后端）：名额/费用处理 → grantActivityPoints 按达成项发放分级积分
   → rewardConfig 权益发放 → SOP 模板消息（报名确认/开场提醒）
```

## 七、错误处理

| 场景 | 处理 |
|------|------|
| unlockCheck 接口异常 | 前端降级：`pointsPreview` 用固定文案值，引导仍可走（积分以后端实际发放为准） |
| 二维码接口异常/未配置 | 跳过 follow 步，不阻塞报名 |
| 关注事件回调延迟 | 「我已关注，刷新」可重复点击轮询，未检测到则 toast 提示 |
| earnPoints 失败（规则未配置等） | 报名主流程不受阻，积分发放异常 catch 后 warn 日志（与现有 grantShareReward 容错一致） |
| 微信 userinfo 缺失头像 | 仅补充存在的字段，缺失则跳过 |

## 八、配置变更

- zhao-point `config/index.ts`：新增 `activity_signup_auth`(+5)、`activity_signup_contact`(+20)、`activity_signup_survey`(+50)；`follow_official_account` 默认 10→50。
- **注意**：按项目经验，zhao-point 后端改配置/代码后需重新构建并部署，否则规则不生效。

## 九、验证方式

1. 后端单测/接口验证：
   - `unlockCheck` 无 rewardConfig 活动返回 `pointsPreview` 各分项正确。
   - `signup` 后积分记录含基础5 + 各达成项，金额正确。
   - 关注奖励 isOneTime 防重（二次报名不重复发关注分）。
2. 前端（微信环境模拟）：
   - 无 rewardConfig 活动：点报名出现对比法引导 → 完整走完 4 步 → 报名成功。
   - 授权登录回调回详情页恢复引导。
   - 「我已关注，刷新」关注状态刷新与步进推进。
   - 静默登录小字弱化、授权登录突出样式。
3. 回归：有 rewardConfig 活动的既有引导不受影响；非微信环境保持原逻辑。

## 十、范围外（YAGNI）

- 不做报名后补填问卷的积分补发（fillQuestionnaire 仅重算 rewardConfig 权益，不补报名积分）。
- 不做关注状态的主动轮询定时器（依赖用户点击「我已关注，刷新」）。
- 不改动模板消息（act_confirm/act_before/act_waitlisted）既有机制，仅对比法文案引用。
