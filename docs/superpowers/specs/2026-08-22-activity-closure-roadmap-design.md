# 活动闭环剩余开发 设计文档

> 决策：本轮仅规划不开发——沉淀项目经验 + 梳理剩余开发计划。剩余内容按「分享海报补齐 → 评价/复购深化 → 部署上线收尾」三阶段推进，每阶段真正开发时独立走 spec → plan → 执行 → 验收。

## 背景与现状

线上线下活动闭环主链已基本落地并验收（报名→到场→评价→触达→复购→成效看板），覆盖：
- 报名/名额/排期/触达/裂变/转化/成效/画像 8 大环节共 20+ 功能。

经盘点，主链上**唯一明确的未实现缺口是「活动分享海报」**——分享裂变已有积分归因与裂变榜，但缺海报图生成，分享无法视觉化。

## 目标

- 沉淀本轮会话项目级经验教训（活动资源排期 / Playwright 前端冒烟）至项目记忆。
- 输出剩余开发 roadmap：为后续三阶段提供总纲，避免重复开发。

## 三阶段方案

### 阶段 A：分享海报补齐（优先）
- **缺口**：分享裂变无海报图，分享链路不完整。
- **范围**：海报图生成接口（含活动标题/讲师/场次/二维码），二维码带分享人 Invite 码回填裂变归因；运营端/C 端"生成海报/分享"入口。
- **复用**：既有裂变归因、上传通道。

### 阶段 B：评价/复购运营侧深化
- **缺口**：评价采集与复购 SOP 已实现，但运营端缺评价管理与复购线索跟进视图。
- **范围**：评价汇总看板（评分均值趋势/NPS/文本关键词/明细筛选），复购线索名单可查可标记跟进状态。
- **复用**：activity-overview 看板口径、sop job scene（activity.repurchase）。

### 阶段 C：部署上线收尾
- basic pull 至 shao 服务器 pm2 运行；web/shao 构建产物上传 openresty。
- 按记忆部署注意点执行；上线前对全部 accept-*.cjs 跑线上库校验新契约 schema。
- 恢复部署时装调的 pgAdmin / swappiness。

## 关键口径

- 评价汇总口径与 activity-overview 看板保持一致，避免各写一套。
- 复购名单来源 = zhao-sso sop job scene（`activity.repurchase`）。
- 海报二维码须携带分享人标识，与既有裂变归因字段契约对齐。

## 不做（已落地）

报名/签到/候补/排期/触达/频控/SOP/复购SOP/微信模板/裂变归因/课程D7/完课激活/续学推荐/效果总览看板/SOP报表/画像/AB测试，均已验收，不在本轮范围。
