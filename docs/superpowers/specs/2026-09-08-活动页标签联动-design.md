# 线下活动页标签联动设计

日期：2026-09-08
状态：设计待审

## 1. 目标与范围

在活动详情页通过**统一标签体系**联动展示相关内容：相关活动、相关文章、相关案例、相关产品、相关FAQ、相关课程、相关教程。机制为「标签自动聚合 + 运营手动覆盖」。

主场景：先在 [www.joho.cn](http://www.joho.cn) 静态站新建活动详情页（含相关XX区块），H5 端（v.joho.cn shao）二期跟进。

非目标：不新建产品/案例/FAQ/课程/教程的静态站详情页（本期相关XX为「卡片+外跳」）。

## 2. 现状与依据

- 统一标签体系已存在（`zhao-tag` 插件）：`tag` / `tag-group` / `tag-index`（通用索引 `searchByTag(tagId, targetType)` 已实现）。

- 已通过 manyToMany 关联 `plugin::zhao-tag.tag` 的内容类型：article、geo-article、case、product、faq、tutorial、download、compliance（zhao-website）；course、course-lesson（zhao-course，含 sequenceTag）；quiz（zhao-quiz）；venue、lecturer、activity-series（zhao-point）。

- **缺口**：activity 的 `tags` 是 JSON 数组（不在统一体系）；活动页"下次活动推荐"按系列/分类而非标签；无按标签聚合的服务；[www.joho.cn](http://www.joho.cn) 无活动页。

- 管理端已有通用 `TagSelector` 组件（article/product 等编辑页复用）。

- zhao-point 已有公开 API：`GET /v1/activities`、`GET /v1/activities/:documentId`。

## 3. 数据模型变更

### 3.1 activity.tags 对齐统一标签（zhao-point）

- schema：`tags: { type: json }` → `{ type: relation, relation: manyToMany, target: 'plugin::zhao-tag.tag', inversedBy: 'pointActivities' }`（tag 侧补同名 inversedBy）。

- 数据迁移：现有 JSON 标签值按 `name/slug` 匹配或创建 zhao-tag.tag 后写入 relation；脚本化，`DRY=1` 先统计，备份后执行。

- 管理端：活动编辑页 tags 改为复用 `TagSelector`（与 article 等一致）。

### 3.2 activity 新增字段

- `slug`（uid）：静态站 URL 用；H5 现有 `?id=` 查询不受影响。

- `relatedOverride`（json）：`{ articles:[], cases:[], products:[], faqs:[], courses:[], tutorials:[], activities:[] }`，存运营手动固定的推荐（documentId 数组）；聚合=自动∪手动−排除。

- `showRelatedSection`（boolean，默认 true）：活动级开关，完全定制客户可关闭。

## 4. 聚合服务（zhao-tag 插件）

- 新公开接口：`GET /api/zhao-tag/v1/related-by-tags?tags=<tagIds>&types=<types>&limit=N`

- 逻辑：按标签集对每类型各取 top N；仅返回 published（article 等）/非 archived（activity）；排除活动自身；排序：isFeatured 优先 → 最近更新；返回每项：标题、摘要、类型、跳转 URL（course/tutorial → v.joho.cn 页，article/geo-article → 静态站页，其余类型无落地页则 URL 为空）。

- 无 URL 的卡片（案例/产品/FAQ 无落地页时）：仅展示标题+摘要，不可点击，右侧提示"即将上线"。

- 权限：public（仅已发布公开数据）。

- 服务归属 zhao-tag（标签中心），复用/扩展既有 tag-index 检索。

## 5. 静态站活动页（strapi-site）

### 5.1 路由

- `/activity/[slug]`（活动详情，静态生成，`generateStaticParams` 枚举已发布活动 slug）

- `/activities`（活动列表页，构建期枚举）

### 5.2 页面区块（自上而下）

1. 活动头部 Hero：封面（16:9，缺失回退标签色块+类型图标）、状态徽章（报名中/名额紧张/已结束 三色）、H1、时间/地点/主办方元信息、报名 CTA。
2. 宣传内容：简介（富文本）、议程时间线、讲师卡（缺失对应隐藏）。
3. 相关活动（标签推荐，排除自身，横向卡片流）。
4. 相关文章/案例/产品/FAQ/课程/教程（标签聚合，每类型一行卡片+外跳，无内容整行隐藏）。
5. 报名区（客户端实时）：剩余名额/状态，报名→跳 H5 报名页，预约咨询→表单。
6. 站点页脚。

> 位置约束（与 H5 对齐）：相关XX 区块位于宣传内容之后（H5 对应"权益区之后"），不插入宣传区内部。

### 5.3 数据获取（方案 C 混合）

- 构建期：活动详情 + 相关XX 聚合结果 → 静态 HTML（SEO 完整，相关XX 可抓取）。

- 客户端组件：报名状态/剩余名额实时拉取 `GET /api/zhao-point/v1/activities/:documentId`。

### 5.4 SEO

- 活动 `Event` 类型 JSON-LD（名称/时间/地点/主办方）。

## 6. H5 活动详情页二期（shao/pages/activity/detail.vue）

- 新增"相关XX"区块：位置在**权益区（benefit-section，报名后"领取更多权益"）之后**。

- **不干扰约束**：AI 智能定制（promoModules 模块组合）与完全定制（客户 HTML `PromoCustomPage`）两套宣传区渲染逻辑**零改动**；相关XX 作为独立区块追加在权益区后，两条宣传路径均不受影响；`showRelatedSection=false` 时完全定制客户可整体隐藏。

- 数据：客户端运行时调用聚合接口。

- 交互：卡片点击外跳（站内 next/link 式跳转，站外新窗口）。

## 7. 交互逻辑

- 活动状态机：未开始(灰) → 报名中(绿) → 名额紧张(橙，≤5 或 ≤10%) → 已结束(灰)；客户端按 now 与 startAt/endAt/remainingSlots 实时计算，构建期快照为初始态。

- 报名 CTA：未登录→SSO 登录→跳 H5 报名；名额=0→禁用"已报满"；已结束→只读。

- 实时轮询 30s + visibilitychange 前台刷新；接口失败保留构建期快照 + 非阻断提示。

- 无障碍：徽章带文字；折叠区用 `<details>`（SEO 可抓）。

## 8. 边界情况

| 场景      | 行为           |
| ------- | ------------ |
| 封面缺失    | 标签色块 + 类型图标  |
| 讲师/议程缺失 | 对应子区隐藏       |
| 名额=0    | 按钮禁用"已报满"    |
| 已结束     | 报名区只读 + 徽章置灰 |
| 实时失败    | 构建期快照 + 轻提示  |
| 相关XX 全空 | "暂无相关内容"占位   |

## 9. 风险与部署约束

- schema 变更（activity.tags/slug/relatedOverride）需 zhao-point（及 zhao-tag inversedBy）重建 dist + 部署；迁移脚本先 DRY 统计。

- 静态站构建需 API 可达（[www.joho.cn](http://www.joho.cn) 反代已通）；2G 服务器禁止远程构建（本地构建后上传）。

- H5 二期不触碰宣传区渲染逻辑（硬约束）。
