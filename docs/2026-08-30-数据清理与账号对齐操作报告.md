本次目标：

| 项目 | 目标 |

| 用户 ID 对齐 | sso_users 与 up_users 完全一致：admin=1、赵义涛=2、优佳商贸=3、邵林=4、555=5 |

| 学习记录 | 删除超过最大用户 ID（5）的学习记录；保留账号积分字段归零 |
| 报名信息 | 彻底清空活动报名 |

## 3. 执行步骤与过程

### 3.1 执行工具

- `_db_run.cjs`：逐条执行 .sql 的执行器，支持单事务模式（任一语句失败整体回滚）。
- `reset-users-and-points.sql`：账号对齐 + 数据清理主脚本（单事务）。

### 3.2 第一次执行：失败并回滚

运行 `node _db_run.cjs reset-users-and-points.sql quiet tx`：

- Part-A（up_users 对齐、积分/报名清零）：执行成功
- Part-B（sso_users 重排）：执行到 `renumber 1004 -> 4` 时失败

```
[FAIL] duplicate key value violates unique constraint "sso_users_pkey"
>> ROLLBACK (partial state discarded)
```

**原因**：主脚本的 sso 重排映射（`mapping_a`/`mapping_b`）基于「原始未对齐状态」硬编码（依赖 id=15 存在、id=4 空缺）。而库中 sso_users 已处于目标对齐状态，重排逻辑不幂等，导致主键冲突。事务整体回滚，数据未受影响。

### 3.3 诊断确认

- `sso_users` / `up_users` 实际均为 1–5 已对齐状态（此前已完成对齐，本次仅需增量处理）。
- `activity_signups` 存在 6 条（4 active + 2 cancelled）+ 2 条 user_lnk 待清空。

### 3.4 清空报名信息

单独执行 `_clear_signups.sql`（单事务）：

```
DELETE FROM activity_signups_user_lnk  → rc=2
DELETE FROM activity_signups           → rc=6
```

### 3.5 序列校准

`up_users_id_seq` / `sso_users_id_seq` 校准为 `setval(seq, 5, true)`，新用户 next_id = 6。

### 3.6 主脚本幂等修复 + 重跑

对 `reset-users-and-points.sql` 做两处修正：

1. **新增 B0 幂等守卫**：检测 sso_users 是否已处于目标状态（1–5 且用户名匹配），已对齐则跳过重排，脚本可安全重跑。
2. **统一 setval 语义**：`setval(seq, max(id), true)`，使 `nextval = max+1`，与验证口径一致。

重跑结果（幂等通过）：

```
Part-A: 积分/报名表清零 = 0
Part-B: >> sso 已对齐，跳过重排
== reset-users-and-points.sql: ok=1 fail=0
```

## 5. 微信报名未获得积分问题

- **根因**：用户身份桥接错位 —— 同一用户在 sso_users 与 up_users 的 ID 不一致，报名/学习记录写入错误的 user_id，积分未记到微信账号名下。
- **修复**：ID 对齐（见上）+ 历史数据合并 + 保留账号学习/报名积分字段归零（points_earned=0 / is_points_claimed=false / points_charged=0）。
- **校验口径**：报名后查询 zhao_point_records 与学习进度归属，确认记到正确的 sso 用户下。
