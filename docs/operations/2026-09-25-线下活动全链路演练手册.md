# 线下活动全链路生产演练手册

日期：2026-09-25 ｜ 执行前必读：[计划1](../superpowers/plans/2026-09-25-线下活动缺口补齐计划1.md)、[计划2](../superpowers/plans/2026-09-25-线下活动缺口补齐计划2.md)

## 0. 前置与已知事实

- **账号**：管理端 `admin` / `Admin@12345`（channel-admin，活动管理可用）→ `POST /api/zhao-auth/v1/admin/auth/local` 拿 jwt。C 端用户走 SSO，测试用户注册接口按 zhao-auth 既有 register 流程；若无可用 SSO 测试用户，先解决 C 端 JWT 获取再开跑（S1 前置卡点）。
- **演练活动参数**：标题`【演练】勿报名-20260925`、渠道=平台根渠道(channel1)、容量 2、免费、报名窗=创建时起 10 分钟、活动开始时间=+30 分钟、formConfig 最简（姓名 1 字段）、preQuestionnaire 配 1-2 题（供 S16 导出）、管理端选择一个集合点（供 S17；生产无自提点数据，先在管理端真实自建 1 条）。
- **接口**（本机 curl 走 `http://localhost:1337`，生产走 `https://joho.cn`，C 端路径前缀 `/api`）：
  - 报名 `POST /api/zhao-point/v1/my/activity/signup` body `{activityId}`（activityId 用 documentId）
  - 取消 `POST /api/zhao-point/v1/my/activity/:documentId/cancel`
  - 自助签到 `POST /api/zhao-point/v1/my/activity/:documentId/checkin` body `{method:"self"}`
  - 出码 `POST /api/zhao-point/v1/my/activity/:documentId/checkin-ticket`
  - 扫码核销 `POST /api/zhao-point/v1/admin/adm/activities/:documentId/scan-checkin` body `{code:"atk:<token>"}`
  - 手动核销同上路径 body `{userId, reason}`
  - 导出 `GET /api/zhao-point/v1/admin/adm/activities/:documentId/signups/export`
  - C 端详情 `GET /api/zhao-point/v1/activities/:documentId`
- **核对表**：`activity_signups`（冗余列 activity_id/user_id）、`activity_attendances`、`activity_checkin_tickets`、`up_users`、积分记录表；DB 访问 `ssh joho` + base64 psql（容器 `1Panel-postgresql-pIe0`，库 strapi）。注意 `zhao_point_rules` 表名带前缀。
- **生产现状**：积分规则已补种 50 条（含 activity_signup=5/activity_attend=20）；`checkin_tickets.token` NOT NULL；生产 `activity_signups` 为 0 行。

## 1. 演练步骤（每步记录：实测结果 + 截图/SQL 输出）

| # | 步骤 | 操作 | 期望 |
|---|------|------|------|
| S1 | 满员报名 | 用户 A、B 依次报名 | 均返回成功（active）；`activity_signups` 出现 2 行 active，activity_id/user_id 冗余列已写 |
| S2 | 候补 | 用户 C 报名 | 返回 `waitlisted:true, position:1`，status=waiting |
| S3 | 双击并发 | 用户 A 同 JWT 两个并发 signup | 恰一条成功，另一条幂等返回；无重复行（部分唯一索引兜底） |
| S4 | 取消+递补 | A 取消 | A 收取消确认通知；C 转 active 并收转正通知（站内信） |
| S5 | 并发取消 drill | 重新满员+候补后 A、B 两并发 cancel | 仅一次 promote；C 只收一条转正通知；名额/退款只动一次 |
| S6 | 取消后重报 | A 再报名 | 新行 active，旧行 cancelled 保留，唯一索引不误伤 |
| S7 | 改期群发 | 管理端把活动开始时间改到 +2 小时 | active+waiting 用户全部收到「改期」站内信；pm2 日志 `broadcast rescheduled`；改回原时间不再群发（幂等键生效） |
| S8 | 扫码核销 | 活动改为过去时段 → C 端出码 → 管理端扫码页/curl 核销 | 核销成功；`activity_attendances.method='worker_scan'` 且 `signups.attended_at` 同步非空（两视图同源） |
| S9 | 票据幂等 | 同 token 二次核销 | 返回 `ticket_used` |
| S10 | 票据过期 | 重新出码等 5 分钟后核销 | 返回 `ticket_expired`，票据状态置 expired |
| S11 | 自助签到 | C 端 `checkin {method:"self"}` | 成功；attendance method=self |
| S12 | 手动核销 | 管理端 manual 核销不填理由 | 返回 `reason_required`；填 ≥2 字符理由后成功且审计含操作者 |
| S13 | 导出核对 | 导出 CSV | 9 固定列+formConfig 列+问卷列；已到场/未到场/已取消三种取值与 DB 一致 |
| S14 | 积分账实 | 演练用户逐笔对账 | 报名(+5)/到场(+20)/取消退费 往返一致；`SUM` 与最新余额相符（规则已补种，此前规则缺失会发不出分） |
| S15 | 集合点展示 | C 端详情页 | 展示集合点名称+地址；清空集合点后区块消失 |
| S16 | 下架收尾 | 演练活动 unpublish | active+waiting 用户收到「取消」通知（幂等键 activity:cancelled）；C 端列表不再可见 |
| S17 | 数据留档 | 不删演练数据 | 留作导出/统计样例；验收记录表填齐 |

## 3. 风险与中止条件

- C 端 JWT 拿不到 → 中止 C 端段，先报告卡点（不阻塞管理端 S7/S12/S13）
- 任何一步与期望不符 → 停止后续依赖步骤，记录现场（日志+SQL），按设计文档风险点排查
