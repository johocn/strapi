# SSO 邀请码闭环与 C 端用户对齐

> 日期：2026-09-04 ｜ 性质：技术实现记录（留存备案）

## 一、闭环目标

微信转发邀请码从「分享 → 落地 → SSO 注册 → 建分销 → C 端回写」全链路不断、不糊：

- **A. 建分销不断**：SSO 每种注册/登录入口都据 `invite_code` 建立分销关系（`sso_referral_relations` / `sso_invite_usages` / `use_count` / `invited_by`）。
- **B. 两个邀请码回传 C 端**：SSO 登录/注册成功后返回 `user`，同时带：
  - `ownInviteCode`：SSO 新生成的用户专属邀请码
  - `inviteCodeUsed`：本次注册/登录用的邀请码（被谁邀请）
- **C. C 端 user.inviteCode 恒等于 SSO ownInviteCode**：不回退成 C 端临时 `SL` 码 / 本地分享码。

## 二、落地消费链路

```
分享人(已登录)转发带真实邀请码
  → 落地页 handleInviteLink 存入 storage(localStorage)
  → SSO 模式 buildSsoPageUrl 读 storage 拼进 ssoUrl?invite_code=
  → SSO 注册/登录收到 invite_code → buildReferralRelation 建分销
  → 返回 user{ inviteCode=own, ownInviteCode, inviteCodeUsed }
  → C 端 auth-callback setUser(user) 落 storage + syncSsoProfile 对齐 up_users
```

## 三、本次改动点

### zhao-sso `server/src/services/sso-auth.ts`
- 密码登录 / 短信登录 / 注册三处返回 user 对象新增字段：
  ```ts
  inviteCodeUsed: inviteCode || null,   // 本次用的邀请码（被谁邀请）
  ```
  与既有 `inviteCode` / `ownInviteCode`（SSO 新生成码）一并返回。
- 建分销调用（既有，确认无误）：三处入口均 `await buildInviteRelation(user.id, inviteCode, appCode, channelCode)`。

### C 端 `auth-callback.vue`（无需改动）
- `setUser(user)` 原样保存 SSO 返回的 user，`inviteCode`/`inviteCodeUsed` 随之落 C 端 storage。
- `syncSsoProfileAfterLogin` 调 `/zhao-auth/v1/auth/sync-sso-profile` 回写 up_users。

## 四、C 端 up_users 对齐规则（zhao-auth `auth.service.ts` syncSsoProfile）

以 `ssoId` 为唯一对齐键，**严格保持 `up_users.id = sso_users.id`**：

| 字段 | 对齐逻辑 | 说明 |
|------|----------|------|
| `sso_id` | `exist.sso_id==null` 时补 `=ssoId` | 身份桥接 |
| `invite_code` | 写入 SSO own 邀请码；占位 `U{id}` 或为空时覆盖 | C 端 user.inviteCode 对齐 SSO |
| `nickname` | 有值或原为空时写入 | |
| `avatar` | 有值则写入 | |
| 存在性 | 无记录则按 `id=ssoId` 插入 | 懒对齐兜底 |
