第一章 系统概述

本系统基于 Odoo 19 进行二次开发，专为超市/零售业态打造，覆盖前台收银、会员管理、班次交接、支付对账、库存管理全链路。系统由多个定制模块协作完成，以下为模块架构与数据流说明。

1.3 数据流：前台销售 → POS收银 → 会员积分 → 财务记账

一笔完整的交易数据流转如下：

  1. 前台销售：收银员在 POS 触摸屏上通过扫码或搜索选择商品，系统实时从 product 模块获取商品信息（名称、价格、库存、条码）。
  2. POS 收银：zhao_market_pos 计算商品金额、应用促销/会员价，生成销售订单（pos.order）。
  3. 会员识别：如果顾客出示会员卡（扫码或手机号），zhao_member 查询会员信息，zhao_member_points 计算本次可获积分。
  4. 支付结算：收银员选择支付方式（聚合码/现金/刷卡），zhao_pos_receipt 处理聚合码支付回调，确认支付成功后订单状态变为"已付款"。
  5. 小票打印：zhao_pos_print 驱动 58mm/80mm 打印机输出小票，zhao_pos 提供中文小票模板。
  6. 会员积分：支付成功后，zhao_member_points 自动增加会员积分；若使用积分抵扣，则同时扣减积分。
  7. 库存扣减：stock 模块自动扣减对应门店的库存量（stock.move）。
  8. 财务记账：account 模块生成应收/收款会计凭证，完成财务入账。
  9. 班次记录：zhao_pos_shift 记录该笔交易所属班次，用于交班盘点。
提示： 如果退货发生，数据流逆向执行——积分回滚、库存恢复、红字冲销会计凭证。zhao_member_points 模块处理退货时的积分回滚逻辑。

第二章 POS收银操作

2.1 登录与开台

2.1.1 系统登录

  1. 打开 POS 应用：在浏览器中访问 http://<服务器地址>/pos，或在 Odoo 后台点击"POS"应用图标。
  2. 输入凭证：输入收银员用户名和密码，点击"登录"。
  3. 选择门店：如果账号关联多个门店，系统弹出门店选择对话框，选择当前所在门店。
  4. 进入 POS 界面：登录成功后进入 POS 触摸屏主界面，左侧为商品区，右侧为购物车区。

2.1.2 开台（开班）

  1. 登录后点击右上角菜单按钮（☰），选择"开班"。
  2. 系统弹出钱箱初始金额对话框，输入开班备用金金额（如 500 元）。
  3. 确认后系统调用 zhao_pos_shift 创建新班次记录，状态为"进行中"。
  4. 开班成功后，POS 界面进入可收银状态，底部显示当前班次编号和收银员姓名。
注意： 开班后请勿关闭浏览器，否则可能导致未保存的订单丢失。如需临时离开，请使用"锁屏"功能。

2.2 商品扫码/选品

2.2.1 扫码添加

  1. 确保扫码枪已连接至收银机，光标聚焦在 POS 搜索框中。
  2. 扫描商品条码，系统自动识别条码，查询 product 模块匹配商品。
  3. 匹配成功后，商品自动添加至右侧购物车列表，数量默认为 1。
  4. 如需修改数量，点击购物车中该商品行，使用数字键盘输入新数量。

2.2.2 手动选品

  1. 在左侧商品区浏览商品分类，点击分类标签切换显示。
  2. 点击目标商品，商品即添加至购物车。
  3. 也可在搜索框输入商品名称关键字（支持模糊搜索），从搜索结果中选择。
  4. 支持多规格商品（如不同口味/规格），选择后弹出规格选择对话框。
提示： 搜索框支持扫描条码和手动输入两种模式，无需切换。商品列表支持网格视图和列表视图切换。

2.3 挂单与取单

2.3.1 挂单

  1. 在购物车商品已选好但顾客暂未结算时，点击"挂单"按钮。
  2. 系统提示输入挂单备注（可选，如"顾客去取钱"），确认后挂单成功。
  3. 挂单后购物车清空，可继续服务下一位顾客。
  4. 挂单记录保存在当前班次中，不会丢失。

2.3.2 取单

  1. 点击"取单"按钮，系统列出当前班次所有挂单记录。
  2. 列表显示：挂单时间、商品数量、金额合计、备注。
  3. 点击目标挂单行，选择"取单"恢复购物车。
  4. 恢复后可继续添加商品或直接结算。
注意： 挂单仅在同一 POS 设备上可取出。换班后挂单将自动转为"已取消"状态。

2.4 会员识别

2.4.1 扫码识别

  1. 在购物车页面点击"会员"按钮。
  2. 使用扫码枪扫描会员卡上的条码或二维码。
  3. 系统调用 zhao_member 查询会员信息，显示会员姓名、等级、可用积分。
  4. 确认后，本次消费自动关联该会员，享受会员价和积分累积。

2.4.2 手机号识别

  1. 点击"会员"按钮，选择"手机号查询"。
  2. 在数字键盘输入会员注册手机号。
  3. 系统查询并显示匹配的会员信息，确认后关联。
  4. 如果手机号未注册，可点击"快速开卡"引导顾客注册。
提示： 会员关联后，购物车商品单价自动切换为会员价（如有），底部显示"已享会员折扣"提示。

2.5 结算

2.5.1 聚合码支付

  1. 购物车确认无误后，点击"结算"按钮。
  2. 选择支付方式为"聚合码支付"。
  3. 系统生成动态收款二维码（微信/支付宝二合一），显示在顾客屏或收银副屏上。
  4. 顾客使用微信/支付宝扫码支付。
  5. zhao_pos_receipt 模块监听支付回调，支付成功后自动关闭二维码并跳转至小票打印页面。
  6. 如果支付超时或失败，可选择"重新生成二维码"或切换其他支付方式。

2.5.2 现金支付

  1. 选择"现金"支付方式。
  2. 系统显示应收金额，输入顾客支付的现金金额。
  3. 系统自动计算找零金额，显示在屏幕上。
  4. 确认后完成交易，钱箱弹开（需连接钱箱设备）。

2.5.3 刷卡支付

  1. 选择"刷卡"支付方式（银行卡/储值卡）。
  2. 在 POS 刷卡器上刷卡，系统读取卡号。
  3. 输入银行卡密码（如需要），或选择"免密支付"。
  4. 等待支付网关确认，成功后完成交易。
支付方式适用场景到账时间手续费
聚合码支付微信/支付宝扫码T+10.38% ~ 0.6%
现金线下现金交易即时无
刷卡银行卡/储值卡T+1按银行费率

2.6 退款操作

2.6.1 整单退款

  1. 在主界面点击"退款"按钮，进入退款模式。
  2. 输入原始订单号（扫描小票条码或手动输入）。
  3. 系统查询出原始订单详情，显示商品列表、金额、支付方式。
  4. 确认退款原因为整单退款，系统自动计算退款金额。
  5. 选择退款方式（原路退回/现金退款），确认后执行退款。
  6. 退款成功后：zhao_member_points 回滚该笔消费获取的积分；stock 恢复库存；account 生成红字冲销凭证。

2.6.2 部分退款

  1. 在退款模式中查询原始订单。
  2. 在商品列表中勾选需要退款的商品项，取消勾选不退款的商品。
  3. 系统自动计算部分退款金额。
  4. 确认后执行退款，积分按比例回滚，库存按退款数量恢复。
注意： 退款操作需要店长权限或店长授权确认。超过 7 天的交易建议通过后台手工退款处理。

2.7 日结操作

  1. 营业结束后，在 POS 主界面点击"日结"按钮。
  2. 系统自动汇总当前班次数据：
    • 交易总笔数
    • 各支付方式金额汇总
    • 退款总金额
    • 会员消费金额
    • 积分发放/消耗统计
  3. 打印日结小票，包含上述汇总数据。
  4. 系统自动关闭当前班次，生成班次报告。
  5. 日结完成后，如需继续收银需要重新开班。

第三章 商品管理

3.1 商品创建与分类

3.1.1 创建商品

  1. 在 Odoo 后台进入"POS → 商品 → 商品"菜单。
  2. 点击"新建"按钮，填写商品信息：
    • 商品名称：必填，显示在小票和屏幕上
    • 商品类型：储值商品/服务/消耗品
    • 内部参考：内部编码，用于管理
    • 条码：商品条码（EAN-13 或自定义）
    • 销售价格：标准零售价
    • 成本价格：进货成本
    • 分类：选择所属商品分类
  3. 填写完成后点击"保存"。

3.1.2 商品分类管理

  1. 进入"POS → 商品 → 商品分类"菜单。
  2. 支持多级分类：如"食品 → 零食 → 膨化食品"。
  3. 每个分类可设置是否在 POS 前台显示，以及显示顺序。
  4. 分类可关联默认税率。

3.2 库存管理

系统使用 Odoo 原生 stock 模块进行库存管理，支持多仓库（多门店）库存隔离。

3.2.1 库存盘点

  1. 进入"库存 → 操作 → 盘点"菜单。
  2. 点击"新建"，选择盘点仓库/门店。
  3. 系统自动加载当前库存数量，填写实际盘点的数量。
  4. 确认差异，系统自动生成库存调整单（stock.inventory.adjustment）。

3.2.2 库存调拨

  1. 进入"库存 → 操作 → 调拨"菜单。
  2. 新建调拨单，选择"源位置"和"目标位置"（仓库到门店，门店到门店等）。
  3. 添加调拨商品和数量，确认后生成移库单。
  4. 源仓库确认出库，目标仓库确认入库。

3.2.3 库存预警

在商品表单中设置"最小库存量"和"最大库存量"。当库存低于最小值时，系统自动生成补货预警通知。可在"库存 → 报告 → 库存预警"中查看。

3.3 价格策略

3.3.1 会员价

  1. 在商品编辑页面，找到"会员价格"字段。
  2. 可设置"普通会员价"和"高级会员价"两档价格。
  3. 当 POS 中识别会员后，系统自动应用对应等级的会员价。
  4. 会员价在购物车中以绿色字体标注，并显示"会员优惠 X 元"。

3.3.2 促销价

  1. 进入"POS → 促销活动"菜单。
  2. 新建促销活动，设置：
    • 促销名称、起止时间
    • 适用商品范围（指定商品、指定分类或全场）
    • 促销类型：折扣（百分比）/ 一口价 / 买赠
    • 限购数量（可选）
  3. 保存后促销活动自动生效，POS 收银时自动计算促销价。
价格类型优先级说明
促销价最高覆盖其他所有价格，活动期间自动生效
会员价中仅识别会员后生效，按会员等级匹配
标准零售价低默认销售价格，无会员或促销时使用

3.4 条码管理

  1. 系统支持标准 EAN-13 条码和自定义内部条码。
  2. 在商品编辑页面"条码"字段输入条码号。
  3. 支持批量生成条码：勾选多个商品，点击"操作 → 生成条码"。
  4. 条码打印：进入"POS → 条码打印"菜单，选择商品，打印条码标签。
  5. 如果条码冲突，系统会提示"条码已被占用"。

第四章 会员管理

4.1 会员开卡

4.1.1 实体卡开卡

  1. 在 POS 后台进入"会员 → 会员卡 → 新建"。
  2. 填写会员基本信息：姓名、手机号、性别、生日。
  3. 选择会员等级（默认"普通会员"）。
  4. 输入实体卡卡号（预印制的卡号），或点击"自动分配"。
  5. 保存后生成会员记录，实体卡激活。

4.1.2 电子卡开卡

  1. 顾客通过线上商城（shop/）注册，填写手机号并验证。
  2. 系统自动创建电子会员卡，关联微信/支付宝账号。
  3. 也可在 POS 端由收银员协助开卡：点击"会员 → 快速开卡"，输入手机号即可。
  4. 电子卡生成后，会员可在微信小程序中查看卡号和二维码。

4.2 会员等级设置

  1. 进入"会员 → 设置 → 会员等级"菜单。
  2. 系统预设等级：普通会员、银卡会员、金卡会员、钻石会员。
  3. 编辑每个等级：
    • 等级名称
    • 升级条件（累计消费金额或积分数量）
    • 等级权益（折扣率、积分倍率、生日礼遇等）
    • 保级条件（年度消费金额要求）
  4. 等级自动升降：系统每天定时任务检查会员消费数据，自动升级/降级。

4.3 积分规则配置

  1. 进入"会员 → 设置 → 积分规则"菜单。
  2. 新建积分规则：
    • 规则名称：如"消费赠积分"
    • 触发事件：订单完成 / 注册 / 签到 / 自定义
    • 积分计算方式：按消费金额比例（每 1 元得 1 积分）或固定值
    • 适用会员等级：可选全部或指定等级
    • 积分上限：单笔交易最高可获积分
  3. 积分抵扣规则：
    • 设置积分抵扣比例（如 100 积分 = 1 元）
    • 设置抵扣上限（单笔订单最高抵扣金额）
    • 设置最低消费金额（满 X 元可用积分）
  4. 保存后规则即时生效。

4.4 积分查询与调整

4.4.1 积分查询

在"会员 → 会员卡"中打开会员详情页，查看积分汇总：

  • 当前可用积分
  • 累计获得积分
  • 累计使用积分
  • 积分明细（按时间倒序，显示每笔积分的来源/去向）

4.4.2 积分手工调整

  1. 在会员详情页点击"积分调整"按钮。
  2. 选择调整类型：增加 / 扣减。
  3. 输入调整数量和调整原因（如"生日赠礼"、"补偿"）。
  4. 确认后生成积分调整记录，会员积分余额实时更新。
注意： 积分调整操作需要管理员权限，所有调整记录均留有操作日志，供后续审计。

第五章 班次管理

5.1 开班操作

  1. 收银员登录 POS 后，点击"开班"。
  2. 系统弹出"钱箱初始金额"输入框，输入当前班次起始备用金。
  3. 系统自动记录：开班时间、收银员、初始金额、门店。
  4. 开班成功后，POS 进入可收银状态，底部栏显示当前班次信息。
  5. 一个门店在同一时间只允许一个进行中的班次。

5.2 交班流程

  1. 收银员点击"交班"，系统进入交班确认流程。
  2. 系统汇总当前班次数据：
    • 交易总笔数（正常 + 退款）
    • 各支付方式应收金额
    • 各支付方式实收金额
    • 会员消费金额
    • 积分发放/消耗
  3. 系统提示"请输入钱箱实盘金额"，收银员清点钱箱后输入实际现金金额。
  4. 系统自动比较应收与实收，计算差额。
  5. 如果差额在允许范围内（可配置，如 ±10 元），交班自动完成。
  6. 如果差额超出范围，进入"差额处理"流程（见 5.4）。

5.3 钱箱盘点

  1. 钱箱盘点在交班时自动触发，也可在班次中手动执行"盘点"。
  2. 盘点时系统列出所有支付方式（现金、聚合码、刷卡等）的理论应收金额。
  3. 收银员逐项清点并输入实际金额。
  4. 系统自动生成差异明细报表。

5.4 差额处理与店长确认

5.4.1 差额处理流程

  1. 当交班时发现现金差额超出允许范围，系统锁定交班操作。
  2. 收银员可填写"差额原因说明"（如：找零错误、遗漏收款等）。
  3. 系统通知店长/管理员（通过系统消息或飞书通知）。
  4. 店长登录系统，进入"班次管理 → 待确认班次"。
  5. 店长审核差额明细和原因说明，可选择：
    • 确认通过：差额由门店承担，班次正常关闭。
    • 驳回：要求收银员重新盘点。
    • 调整：店长手工调整金额（需填写调整原因）。
  6. 店长确认后，班次状态变更为"已关闭"。

第七章 支付管理

7.1 聚合码支付配置

7.1.1 商户接入

  1. 联系微信支付/支付宝服务商，申请商户号，开通聚合码支付功能。
  2. 获取以下参数：
    • 商户号（Merchant ID）
    • 应用 ID（AppID）
    • API 密钥（API Key）
    • 回调地址（Notify URL）
  3. 在 Odoo 后台进入"POS → 设置 → 支付方式 → 聚合码支付"。
  4. 填入上述参数，保存配置。

7.1.2 回调地址配置

  1. 聚合码支付的回调地址需配置为：http://<服务器地址>/pos_receipt/callback
  2. 该地址由 zhao_pos_receipt 模块自动注册，处理支付成功回调。
  3. 回调处理逻辑：
    • 验证签名
    • 更新订单支付状态为"已付款"
    • 触发小票打印
    • 触发积分发放
    • 触发库存扣减

7.1.3 二维码生成

  1. 系统在结算时调用支付网关 API 生成动态二维码。
  2. 二维码有效期为 5 分钟（可配置），超时自动失效。
  3. 顾客扫码后，支付网关通过回调地址通知系统。
  4. 如果未收到回调，可在 POS 端点击"查询支付结果"主动查询。

7.2 支付对账

7.2.1 每日对账

  1. 进入"POS → 报告 → 支付对账"菜单。
  2. 选择对账日期，系统自动汇总：
    • POS 交易记录（各支付方式金额）
    • 支付网关到账记录（需导入支付网关账单）
    • 差异明细（如有）
  3. 系统自动对账匹配，标记"已对账"和"未对账"记录。
  4. 对于未对账记录，手工排查原因（如：支付成功但 POS 未收到回调、退款等）。

7.2.2 对账差异处理

第八章 权限管理

8.1 多门店权限矩阵

zhao_pos_iam 模块实现了三维权限矩阵：用户 × 角色 × 门店。每个用户在不同门店可拥有不同角色，实现精细化的权限控制。

8.2 角色配置

  1. 进入"设置 → 用户 → 角色"菜单。
  2. 系统预置角色：
    • 管理员：所有权限，包括系统配置、模块安装
    • 区域经理：可查看所辖门店所有数据，审核交班、退款
    • 店长：本门店管理权限，商品管理、交班确认、退款审批
    • 收银员：POS 收银操作，无法修改商品、价格、配置
    • 库管员：库存管理权限，入库、出库、盘点
  3. 可新建自定义角色，按功能权限点（如"允许退款"、"允许修改价格"等）进行配置。
  4. 每个角色可设置"可访问门店"范围：全部门店 / 指定门店 / 仅本门店。
提示： 权限修改即时生效，无需重新登录。建议先在实际使用前充分测试权限配置。

8.3 数据隔离规则

zhao_pos_iam 实现的行级数据隔离：

  • 订单数据：收银员只能查看自己创建的订单；店长可查看本门店所有订单；区域经理可查看所辖区域所有订单。
  • 商品数据：商品信息共享，但门店可独立设置"门店可用商品列表"。
  • 会员数据：会员数据全门店共享，但积分操作按门店记录。
  • 班次数据：收银员只可操作自己的班次；店长可查看/确认本门店所有班次。
  • 财务数据：按门店进行财务数据隔离，各门店独立记账。
// 数据隔离实现示例 (Python)
class PosOrder(models.Model):
    _name = 'pos.order'
    _inherit = 'pos.order'

    def _check_access_rule(self):
        """多门店数据隔离"""
        user = self.env.user
        if user.has_group('zhao_pos_iam.group_admin'):
            return  # 管理员全可见
        if user.has_group('zhao_pos_iam.group_region_manager'):
            shops = user.managed_shop_ids  # 区域经理管辖门店
            return self.filtered(lambda o: o.shop_id in shops)
        if user.has_group('zhao_pos_iam.group_shop_manager'):
            return self.filtered(lambda o: o.shop_id == user.shop_id)
        # 收银员仅看自己
        return self.filtered(lambda o: o.create_uid == user)
